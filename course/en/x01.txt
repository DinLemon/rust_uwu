# MODULE x01 | Types, deeper | Const generics, PhantomData, blanket impls, Sized

## LESSON x01-1 | Const generics | 8
:: goals
- Make generics over numbers, not just types
- Write functions for arrays of any length

:: text A number as a type parameter
Generics can be over a type `<T>`, but also over a **value**: `<const N: usize>`. Then `N` is part of the type, and `Matrix<2>` and `Matrix<3>` are different types.

```rust
struct Buffer<const N: usize> {
    data: [u8; N],
}
```
You've seen this already: the array `[T; N]` is exactly a const generic.

> **Analogy:** egg cartons for 6 and for 10. Built the same way, but you can't mix them up: ten eggs don't fit in the six-pack.

:: code
```rust
fn sum<const N: usize>(a: [i32; N]) -> i32 {
    a.iter().sum()
}

fn first_last<T: Copy, const N: usize>(a: [T; N]) -> Option<(T, T)> {
    if N == 0 { None } else { Some((a[0], a[N - 1])) }
}

fn main() {
    println!("{}", sum([1, 2, 3]));
    println!("{}", sum([10; 5]));
    println!("{:?}", first_last(['a', 'b', 'c']));
    println!("{:?}", first_last::<u8, 0>([]));
}
```
```out
6
50
Some(('a', 'c'))
None
```
`N` is known **at compile time**. `sum` for an array of 3 and of 5 elements are two different copies of the code.

:: text Where it helps
- Fixed-size vectors and matrices: `Vec3 = Vector<3>`.
- Heap-free buffers for embedded systems (`heapless::Vec<T, 16>`).
- Size checks at compile time: the compiler won't let you add a `Vector<3>` and a `Vector<4>`.

:: quiz
What is `N` in `struct Ring<const N: usize>`?
[ ] A field of the struct => It's a type parameter; it isn't stored in memory.
[x] A number that becomes part of the type => Right. `Ring<4>` and `Ring<8>` are different types.
[ ] A variable you can change => The value is known at compile time and doesn't change.

```solution
struct Ring<const N: usize> {
    buf: [i32; N],
    start: usize,
    len: usize,
}

impl<const N: usize> Ring<N> {
    fn new() -> Self {
        Ring { buf: [0; N], start: 0, len: 0 }
    }
    fn push(&mut self, x: i32) {
        if self.len < N {
            self.buf[(self.start + self.len) % N] = x;
            self.len += 1;
        } else {
            self.buf[self.start] = x;
            self.start = (self.start + 1) % N;
        }
    }
    fn items(&self) -> Vec<i32> {
        (0..self.len).map(|i| self.buf[(self.start + i) % N]).collect()
    }
}

fn main() {
    let mut r: Ring<3> = Ring::new();
    for x in 1..=5 {
        r.push(x);
    }
    println!("{:?}", r.items());
}
```
```expect
[3, 4, 5]
```
hint: While the buffer isn't full, write at `(start + len) % N` and increase `len`.
hint: When it's full, write at `start` (the oldest) and move `start` by one.

:: recap
- `<const N: usize>` — a generic over a number. `N` is part of the type.
- Functions for arrays of any length: `fn f<const N: usize>(a: [T; N])`.
- Sizes are checked at compile time.

## LESSON x01-2 | PhantomData and marker types | 8
:: goals
- Tag a type with information that isn't in the data
- Make units of measure that can't be mixed up

:: text Same data, different meaning
`Distance<Meters>` and `Distance<Feet>` both hold the same `f64` inside. But you can't add them together.

The `Unit` parameter isn't used in the data. The compiler doesn't like that: "parameter is never used". That's what `PhantomData<Unit>` is for — a zero-size field that says "this type is sort of here".

> **Analogy:** colored stickers on identical jars. Same jar, but red is for spices and blue is for grains.

:: code
```rust
use std::marker::PhantomData;
use std::ops::Add;

#[derive(Debug, Clone, Copy)]
struct Meters;
#[derive(Debug, Clone, Copy)]
struct Feet;

#[derive(Debug, Clone, Copy)]
struct Distance<U> {
    value: f64,
    unit: PhantomData<U>,
}

impl<U> Distance<U> {
    fn new(value: f64) -> Self {
        Distance { value, unit: PhantomData }
    }
}

impl<U> Add for Distance<U> {
    type Output = Distance<U>;
    fn add(self, o: Self) -> Self {
        Distance::new(self.value + o.value)
    }
}

fn main() {
    let a: Distance<Meters> = Distance::new(5.0);
    let b: Distance<Meters> = Distance::new(2.5);
    println!("{}", (a + b).value);
    println!("{}", std::mem::size_of::<Distance<Feet>>());
    // let c: Distance<Feet> = Distance::new(1.0);
    // a + c; // error: different units
}
```
```out
7.5
8
```
`Distance<Feet>` is 8 bytes, like a single `f64`. The marker weighs nothing.

:: quiz
How much memory does a `PhantomData<T>` field take?
[x] Zero bytes => Right. It's only information for the compiler.
[ ] As much as `T` => No, `T` isn't stored there.
[ ] One pointer => There's no pointer at all.

:: deep derive and PhantomData: a catch
`#[derive(Clone, Copy, PartialEq)]` on `Id<T>` requires that **`T` too** is `Clone`/`Copy`/`PartialEq`. Even though `T` isn't stored inside! That's how `derive` works: it adds a bound on every parameter.

So the `Id<User>` from the task won't be `Copy` unless `User` is `Copy`. The workaround is a manual implementation:

```rust
impl<T> Clone for Id<T> { fn clone(&self) -> Self { *self } }
impl<T> Copy for Id<T> {}
```
Or crates like `derive-where`, where you can state the bounds by hand.

:: recap
- `PhantomData<T>` is a zero-size type marker.
- Same data + different markers = different types.
- `impl Type<Marker>` — methods only for a specific marker.

## LESSON x01-3 | Blanket impls and extension traits | 8
:: goals
- Implement a trait for all fitting types at once
- Add your own methods to other people's types

:: text An implementation "for everyone"
A **blanket impl** implements a trait for **any** type that meets a condition:

```rust
impl<T: Display> MyTrait for T { ... }
```
The standard library is built this way: `impl<T: Display> ToString for T` — that's why everything that can `Display` has `.to_string()`.

:: text Extension trait
You can't add a method directly to `str` or `Vec` — they aren't yours. But you can declare **your own** trait with a method and implement it for someone else's type. This is called an **extension trait**:

```rust
trait Shout {
    fn shout(&self) -> String;
}
impl Shout for str {
    fn shout(&self) -> String { self.to_uppercase() + "!" }
}
// "hello".shout() == "HELLO!"
```
The orphan rule isn't broken: the trait is yours.

> **Analogy:** a drill attachment. The drill isn't yours, but the attachment is — and the drill gets a new function.

:: code
An extension for **every iterator** of numbers — a blanket impl and an extension trait together:
```rust
trait Stats: Iterator<Item = i32> + Sized {
    fn mean(self) -> Option<f64> {
        let (sum, n) = self.fold((0i64, 0u32), |(s, n), x| (s + x as i64, n + 1));
        if n == 0 { None } else { Some(sum as f64 / n as f64) }
    }
}

impl<I: Iterator<Item = i32>> Stats for I {}

fn main() {
    println!("{:?}", vec![1, 2, 3, 4].into_iter().mean());
    println!("{:?}", (1..=10).filter(|x| x % 2 == 0).mean());
    println!("{:?}", std::iter::empty::<i32>().mean());
}
```
```out
Some(2.5)
Some(6.0)
None
```
Now **any** `i32` iterator has `.mean()` — even ones that don't exist yet.

[x] The standard library has a blanket impl of `ToString` for all `T: Display` => Right.

## LESSON x01-4 | Sized and ?Sized | 7
:: goals
- Understand what a type without a known size is
- Write functions that accept `str`, `[T]` and `dyn Trait`

:: text Not every type has a known size
Most types have a size known at compile time: `i32` is 4 bytes, `String` is 24 bytes. That's the `Sized` trait.

But some types have **no** known size:
- `str` — a string of any length;
- `[T]` — a slice of any length;
- `dyn Trait` — some type with a trait.

You can't put them in a variable directly — only behind a pointer: `&str`, `Box<[T]>`, `&dyn Trait`.

:: text Implicit Sized
Every `<T>` in a generic really means `<T: Sized>`. The compiler adds it by itself. To allow unsized types as well, you write `?Sized` — "maybe not Sized":

```rust
fn show<T: Display + ?Sized>(x: &T) { println!("{x}"); }
```
Now `show` accepts `&i32`, `&str` and `&dyn Display`.

> **Analogy:** a fixed-size suitcase (`Sized`) versus luggage "of any size, but only on a trolley" (`?Sized` behind a pointer).

:: code
```rust
use std::fmt::Display;

fn show<T: Display + ?Sized>(label: &str, x: &T) {
    println!("{label}: {x} ({} bytes behind the reference)", std::mem::size_of_val(x));
}

fn main() {
    show("number", &7u8);
    show("string", "hello");
    let d: &dyn Display = &3.5f64;
    show("dyn", d);
}
```
```out
number: 7 (1 bytes behind the reference)
string: hello (5 bytes behind the reference)
dyn: 3.5 (8 bytes behind the reference)
```
`size_of_val` finds the size at run time: the string "hello" is 5 bytes.

:: quiz
What does `T: ?Sized` mean?
[ ] `T` definitely has no size => Not "definitely without", but "may be without".
[x] `T` may be unsized, so it's used only behind a pointer => Right.
[ ] `T` is always on the heap => Not necessarily: a `&str` can point anywhere.

:: recap
- `Sized` — the size is known at compile time. Every `<T>` has it by default.

impl<const R: usize, const C: usize> Matrix<R, C> {
    fn transpose(&self) -> Matrix<C, R> {
        let mut out = [[0; R]; C];
        for r in 0..R {
            for c in 0..C {
                out[c][r] = self.0[r][c];
