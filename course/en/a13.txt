## LESSON a13-1 | Step 1: types and parsing a line | 9
:: goals
- Describe a log entry with types

:: text What we're building
The program reads a **log** — a program's event journal — and makes a report: how many errors, and where most of them are.

A log line looks like this:
```
ERROR db: query failed
```
A level (`INFO`, `WARN`, `ERROR`), a module (`db`), a colon and a message.

We'll go through four steps. Each uses Level 2 topics. If something's slipped your mind, the text points to the module.

> **Analogy:** building a construction set. You already know the parts; now we connect them into one little machine.

:: text The FromStr trait
You've written `"42".parse::<i32>()` many times. How does `parse` know how to turn a string into an `i32`? Through the `FromStr` trait.

Implement `FromStr` for your type and `parse` works for it too:

```rust
impl FromStr for Level {
    type Err = ParseError;
    fn from_str(s: &str) -> Result<Level, ParseError> { ... }
}

let lvl: Level = "WARN".parse()?;
```
`type Err` is an associated type (see the "Traits, deeper" module).

:: code
```rust
use std::str::FromStr;

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Level {
    Info,
    Warn,
    Error,
}

#[derive(Debug, PartialEq)]
enum ParseError {
    NoLevel,
    UnknownLevel(String),
    NoMessage,
}

impl FromStr for Level {
    type Err = ParseError;
    fn from_str(s: &str) -> Result<Level, ParseError> {
        match s {
            "INFO" => Ok(Level::Info),
            "WARN" => Ok(Level::Warn),
            "ERROR" => Ok(Level::Error),
            other => Err(ParseError::UnknownLevel(other.to_string())),
        }
    }
}

fn main() {
    println!("{:?}", "WARN".parse::<Level>());
    println!("{:?}", "DEBUG".parse::<Level>());
}
```
```out
Ok(Warn)
Err(UnknownLevel("DEBUG"))
```
`PartialOrd, Ord` in the `derive` let levels be compared and sorted: `Info < Warn < Error` (in declaration order).

:: text An entry without copies
An entry holds **pieces of the original line**, not copies — like the parser from the "Lifetimes, deeper" module:

```rust
#[derive(Debug)]
struct Entry<'a> {
    level: Level,
    module: &'a str,
    msg: &'a str,
}
```
An `Entry` can't outlive the line it was parsed from. In exchange, parsing is very fast.

## LESSON a13-2 | Step 2: statistics | 9
:: goals
- Compute statistics with iterators
- Separate good lines from bad ones

:: text What we count
- How many entries of each level.
- Which module has the most errors.
- How many lines couldn't be parsed.

For counting by key — a `BTreeMap` and `entry().or_insert(0)` (see "Iterators from the inside"). A `BTreeMap` keeps keys in order — the report comes out stable.

:: code
The parser (from step 1) is folded into a few lines to keep the example short. Look at `main`:
```rust
use std::collections::BTreeMap;

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Level { Info, Warn, Error }

struct Entry<'a> { level: Level, module: &'a str }

fn parse_line(line: &str) -> Option<Entry<'_>> {
    let (lvl, rest) = line.split_once(' ')?;
    let level = match lvl { "INFO" => Level::Info, "WARN" => Level::Warn, "ERROR" => Level::Error, _ => return None };
    let (module, _msg) = rest.split_once(": ")?;
    Some(Entry { level, module })
}

const LOG: &str = "INFO db: connected
WARN net: slow response
ERROR db: query failed
INFO web: request /home
ERROR net: timeout
ERROR db: lost connection
oops";

fn main() {
    let (good, bad): (Vec<_>, Vec<_>) = LOG.lines().map(parse_line).partition(|e| e.is_some());
    let entries: Vec<Entry> = good.into_iter().flatten().collect();

    let mut by_level: BTreeMap<Level, usize> = BTreeMap::new();
    for e in &entries {
        *by_level.entry(e.level).or_insert(0) += 1;
    }
    println!("{by_level:?}");
    println!("bad lines: {}", bad.len());
}
```
```out
{Info: 2, Warn: 1, Error: 3}
bad lines: 1
```
- `lines()` — the lines of a text one by one.
- `partition` — split into two piles by a condition.
- `flatten()` removes the `Some` and keeps the entries themselves.

:: quiz
Why use a `BTreeMap` for counting and not a `HashMap`?
[ ] A `HashMap` can't count => It can, it has `entry` too.
[x] A `BTreeMap` keeps keys in order, so the report is always the same => Right. A `HashMap` gives keys in random order.
[ ] A `BTreeMap` is always faster => Not always; here the order is what matters.

struct Entry<'a> { level: Level, module: &'a str }

## LESSON a13-3 | Step 3: report formats | 8
:: goals
- Make several report formats with a trait
- Pick the format at run time with `Box<dyn Report>`

:: text One report, different looks
A person likes text, a spreadsheet likes CSV, another program likes JSON. The counting logic is the same, but the output differs.

We describe the **skill** "render a report" as a trait, and each format implements it its own way (see "Traits, deeper"):

```rust
trait Report {
    fn name(&self) -> &str;
    fn render(&self, counts: &[(&str, usize)]) -> String;
}
```

:: code
```rust
trait Report {
    fn name(&self) -> &str;
    fn render(&self, counts: &[(&str, usize)]) -> String;
}

struct Plain;
struct Bars;

impl Report for Plain {
    fn name(&self) -> &str { "text" }
    fn render(&self, counts: &[(&str, usize)]) -> String {
        counts.iter().map(|(m, n)| format!("{m}: {n}")).collect::<Vec<_>>().join(", ")
    }
}

impl Report for Bars {
    fn name(&self) -> &str { "bars" }
    fn render(&self, counts: &[(&str, usize)]) -> String {
        counts.iter().map(|(m, n)| format!("{m:>4} {}", "#".repeat(*n))).collect::<Vec<_>>().join("\n")
    }
}

fn pick(name: &str) -> Box<dyn Report> {
    match name {
        "bars" => Box::new(Bars),
        _ => Box::new(Plain),
    }
}

fn main() {
    let counts = [("db", 3), ("net", 1), ("web", 2)];
    for choice in ["plain", "bars"] {
        let r = pick(choice);
        println!("[{}]", r.name());
        println!("{}", r.render(&counts));
    }
}
```
```out
[text]
db: 3, net: 1, web: 2
[bars]
  db ###
 net #
 web ##
```
`{m:>4}` right-aligns in 4 characters. That way the bars start evenly.

:: quiz
Why does `pick` return `Box<dyn Report>` and not `impl Report`?

[ ] You can't return `impl` from functions => You can, but only one type.
[ ] `Box` is faster => No, `dyn` is a bit slower; it's there for flexibility.

:: text A big log — several threads
If the log has a million lines, the parsing can be split: each thread takes its own chunk of lines (see "Threads, deeper"). `thread::scope` lets threads look at the shared text without `Arc` and without copies.

:: code
```rust
use std::thread;

fn is_error(line: &str) -> bool {
    line.starts_with("ERROR ")
}

fn main() {
    let log: String = (0..10_000)
        .map(|i| if i % 4 == 0 { "ERROR db: x\n" } else { "INFO web: y\n" })
        .collect();
    let lines: Vec<&str> = log.lines().collect();

    let total: usize = thread::scope(|s| {
        let handles: Vec<_> = lines
            .chunks(2_500)
            .map(|part| s.spawn(move || part.iter().filter(|l| is_error(l)).count()))
            .collect();
        handles.into_iter().map(|h| h.join().unwrap()).sum()
    });
    println!("errors: {total}");
}
```
```out
errors: 2500
```
Four threads of 2500 lines each. The lines are `&str` into the shared `log`; nothing was copied.

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Level { Info, Warn, Error }

struct Entry<'a> { level: Level, module: &'a str, msg: &'a str }

struct Query<'q> {
    min_level: Level,
    module: Option<&'q str>,
}

impl<'q> Query<'q> {
    fn new() -> Self {
        Query { min_level: Level::Info, module: None }
    }
    fn min_level(mut self, l: Level) -> Self {
        self.min_level = l;
        self
    }
    fn module(mut self, m: &'q str) -> Self {
        self.module = Some(m);
        self
    }
    fn matches(&self, e: &Entry) -> bool {
        e.level >= self.min_level && self.module.is_none_or(|m| m == e.module)
    }
}

fn main() {
    let log = [
        Entry { level: Level::Info, module: "db", msg: "connected" },
        Entry { level: Level::Error, module: "db", msg: "query failed" },
        Entry { level: Level::Warn, module: "net", msg: "slow" },
        Entry { level: Level::Warn, module: "db", msg: "retry" },
    ];
    let q = Query::new().min_level(Level::Warn).module("db");
    for e in log.iter().filter(|e| q.matches(e)) {
        println!("{}", e.msg);
    }
}

use std::collections::BTreeMap;

fn main() {
    let modules = ["db", "web", "net", "db", "web", "db", "auth"];
    let mut counts: BTreeMap<&str, usize> = BTreeMap::new();
    for m in modules {
        *counts.entry(m).or_insert(0) += 1;
    }
    let mut top: Vec<(&str, usize)> = counts.into_iter().collect();
    top.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(b.0)));
    for (m, n) in top.iter().take(2) {
        println!("{m}: {n}");
    }
}
