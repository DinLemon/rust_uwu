# MODULE x02 | Тонкости трейтов | dyn-совместимость, апкаст, Any, GAT, impl Trait и async fn в трейтах

## LESSON x02-1 | Что можно делать с dyn и что нельзя | 8
:: goals
- Понять, почему не каждый трейт можно сделать `dyn`
- Исключать отдельные методы через `where Self: Sized`

:: text Правила dyn-совместимости
Чтобы трейт можно было использовать как `dyn Trait`, компилятор должен построить **таблицу методов**. Это невозможно, если метод:
- возвращает `Self` (размер `Self` неизвестен за `dyn`);
- обобщён своим параметром `<T>` (нужна бесконечная таблица — по записи на каждый `T`);
- не принимает `self` вообще (статический метод вроде `fn new()`).

Такой трейт называют **не dyn-совместимым**.

> **Аналогия:** пульт от телевизора: кнопки заранее известны. Кнопку «сделай то, не знаю что» на пульт не поставишь.

:: text Выключить метод для dyn
Если в трейте есть один «неудобный» метод, его можно **исключить** из таблицы:

```rust
trait Shape {
    fn area(&self) -> f64;
    fn scaled(&self, k: f64) -> Self where Self: Sized; // не для dyn
}
```
`where Self: Sized` значит: «этот метод только для конкретных типов». Остальные методы работают и через `dyn Shape`.

:: code
```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String {
        String::from("фигура")
    }
    fn scaled(&self, k: f64) -> Self
    where
        Self: Sized;
}

#[derive(Debug)]
struct Square(f64);

impl Shape for Square {
    fn area(&self) -> f64 { self.0 * self.0 }
    fn scaled(&self, k: f64) -> Self { Square(self.0 * k) }
}

fn main() {
    let big = Square(2.0).scaled(3.0);
    println!("{big:?}");
    let shapes: Vec<Box<dyn Shape>> = vec![Box::new(big), Box::new(Square(1.0))];
    for s in &shapes {
        println!("{}: {}", s.name(), s.area());
    }
}
```
```out
Square(6.0)
фигура: 36
фигура: 1
```
Убери `where Self: Sized` и посмотри ошибку: трейт перестанет быть dyn-совместимым.

:: quiz
Какой метод делает трейт не dyn-совместимым?
[ ] `fn area(&self) -> f64` => Обычный метод, с ним всё хорошо.
[x] `fn clone_me(&self) -> Self` => Верно. Размер `Self` за `dyn` неизвестен.
[ ] `fn name(&self) -> String` => `String` — известный тип, всё хорошо.

:: task
Трейт `Animal` не компилируется как `dyn`, потому что в нём есть `fn new(name: &str) -> Self`. Исключи этот метод из таблицы, чтобы `Vec<Box<dyn Animal>>` заработал.
```rust
trait Animal {
    fn new(name: &str) -> Self;
    fn speak(&self) -> String;
}

struct Cat(String);

impl Animal for Cat {
    fn new(name: &str) -> Self { Cat(name.to_string()) }
    fn speak(&self) -> String { format!("{}: мяу", self.0) }
}

fn main() {
    let zoo: Vec<Box<dyn Animal>> = vec![Box::new(Cat::new("Мурка"))];
    for a in &zoo {
        println!("{}", a.speak());
    }
}
```
```solution
trait Animal {
    fn new(name: &str) -> Self
    where
        Self: Sized;
    fn speak(&self) -> String;
}

struct Cat(String);

impl Animal for Cat {
    fn new(name: &str) -> Self { Cat(name.to_string()) }
    fn speak(&self) -> String { format!("{}: мяу", self.0) }
}

fn main() {
    let zoo: Vec<Box<dyn Animal>> = vec![Box::new(Cat::new("Мурка"))];
    for a in &zoo {
        println!("{}", a.speak());
    }

```
```expect
Мурка: мяу
```
hint: Допиши к `new` условие `where Self: Sized`.

:: recap
- `dyn` нужен трейт без `-> Self`, без обобщённых методов и без методов без `self`.
- `where Self: Sized` убирает метод из таблицы `dyn`.
- Остальные методы через `dyn` работают.

## LESSON x02-2 | Апкаст и Any | 8
:: goals
- Превращать `&dyn Sub` в `&dyn Super`
- Узнавать конкретный тип за `dyn Any`

:: text Апкаст
Если `trait Pet: Animal` (Pet требует Animal), то любой `&dyn Pet` можно превратить в `&dyn Animal`. Это **апкаст** — переход к более общему трейту. Пишется просто как присваивание.

```rust
let p: &dyn Pet = &dog;
let a: &dyn Animal = p; // апкаст
```

:: code
```rust
trait Animal {
    fn name(&self) -> String;
}
trait Pet: Animal {
    fn owner(&self) -> String;
}

struct Dog;
impl Animal for Dog {
    fn name(&self) -> String { String::from("Шарик") }
}
impl Pet for Dog {
    fn owner(&self) -> String { String::from("Дядя Фёдор") }
}

fn describe(a: &dyn Animal) {
    println!("животное: {}", a.name());
}

fn main() {
    let pets: Vec<Box<dyn Pet>> = vec![Box::new(Dog)];
    for p in &pets {
        println!("хозяин: {}", p.owner());
        describe(p.as_ref()); // &dyn Pet -> &dyn Animal
    }
}
```
```out
хозяин: Дядя Фёдор
животное: Шарик
```

:: text Any — узнать, кто там
`std::any::Any` — трейт, который есть почти у всех типов. Через `dyn Any` можно спросить: «а не `String` ли ты?» — и получить ссылку на конкретный тип.

```rust
use std::any::Any;
fn inspect(x: &dyn Any) {
    if let Some(s) = x.downcast_ref::<String>() { println!("строка {s}"); }
}
```
Это **downcast** — переход к конкретному типу. Пользуются им редко: обычно лучше `enum`. Но для плагинов и разнородных хранилищ — выручает.

:: code
```rust
use std::any::Any;

fn inspect(x: &dyn Any) -> String {
    if let Some(n) = x.downcast_ref::<i32>() {
        format!("число {n}")
    } else if let Some(s) = x.downcast_ref::<String>() {
        format!("строка «{s}»")
    } else {
        String::from("что-то другое")
    }
}

fn main() {
    let items: Vec<Box<dyn Any>> = vec![Box::new(7), Box::new(String::from("кот")), Box::new(1.5)];
    for it in &items {
        println!("{}", inspect(it.as_ref()));
    }
}
```
```out
число 7
строка «кот»
что-то другое
```

:: quiz
Что такое downcast?
[ ] Превращение `&dyn Pet` в `&dyn Animal` => Это апкаст: к более общему.
[x] Попытка получить конкретный тип из `dyn Any` => Верно. Может не получиться — поэтому `Option`.
[ ] Приведение числа к меньшему типу => Это `as`, другое дело.

```rust

fn sum_ints(items: &[Box<dyn Any>]) -> i32 {
    // твой код
}

fn main() {

        Box::new("строка"),
```

```solution
    items.iter().filter_map(|b| b.downcast_ref::<i32>()).sum()
}

fn main() {
    let items: Vec<Box<dyn Any>> = vec![
        Box::new(10),
        Box::new("строка"),
        Box::new(5),

}
```
```expect
15
```
hint: `b.downcast_ref::<i32>()` вернёт `Option<&i32>`. Подойдёт `filter_map`.

:: recap
- Апкаст: `&dyn Sub` → `&dyn Super`, если `trait Sub: Super`.
- `dyn Any` + `downcast_ref::<T>()` — узнать конкретный тип.
- Downcast — крайняя мера; чаще лучше `enum`.

## LESSON x02-3 | GAT: заимствующий итератор | 9
:: goals
- Понять, что такое ассоциированный тип с параметром
- Написать итератор, который выдаёт ссылки на свой внутренний буфер

:: text Проблема: итератор не может одолжить себя
Обычный `Iterator` выдаёт элементы, которые живут **независимо** от вызова `next`. Поэтому нельзя написать итератор, который на каждом шаге возвращает `&mut` на **свой** буфер: два таких элемента одновременно дали бы две `&mut` на одно.

Нужен трейт, где тип элемента **зависит от времени заимствования** самого итератора:

```rust
trait LendingIterator {
    type Item<'a> where Self: 'a;
    fn next(&mut self) -> Option<Self::Item<'_>>;
}
```
`type Item<'a>` — **обобщённый ассоциированный тип** (GAT, generic associated type).

> **Аналогия:** библиотекарь даёт тебе книгу почитать на месте. Следующую получишь, только когда вернёшь эту.

:: code
```rust
trait LendingIterator {
    type Item<'a>
    where
        Self: 'a;
    fn next(&mut self) -> Option<Self::Item<'_>>;
}

// Окна по 2 элемента, которые можно МЕНЯТЬ
struct WindowsMut<'s> {
    data: &'s mut [i32],
    pos: usize,
}

impl<'s> LendingIterator for WindowsMut<'s> {
    type Item<'a> = &'a mut [i32] where Self: 'a;
    fn next(&mut self) -> Option<&mut [i32]> {
        let start = self.pos;
        if start + 2 > self.data.len() {
            return None;
        }
        self.pos += 1;
        Some(&mut self.data[start..start + 2])
    }
}

fn main() {
    let mut v = [1, 2, 3, 4];
    let mut it = WindowsMut { data: &mut v, pos: 0 };
    while let Some(w) = it.next() {
        w[1] += w[0]; // накопительная сумма
    }
    println!("{v:?}");
}
```
```out
[1, 3, 6, 10]
```
Обычный `windows` даёт только `&[T]`. Изменять через окна стало можно благодаря GAT.

:: text Ограничение while let
С `LendingIterator` не работают `for`, `map`, `collect` — они рассчитаны на обычный `Iterator`. Пишут `while let Some(x) = it.next()`. Зато безопасно: следующий элемент не получить, пока жив предыдущий.

:: quiz
Почему обычный `Iterator` не может выдавать `&mut` на свой внутренний буфер?
[x] `collect` мог бы собрать сразу несколько `&mut` на одни данные => Верно. Элементы обычного итератора живут независимо друг от друга.
[ ] `&mut` вообще нельзя возвращать из методов => Можно, просто не так.
[ ] Буфер обязан быть в куче => Дело не в куче.

```solution
trait LendingIterator {
    type Item<'a>
    where
        Self: 'a;
    fn next(&mut self) -> Option<Self::Item<'_>>;
}

struct Upper<'t> {
    lines: std::str::Lines<'t>,
    buf: String,
}

impl<'t> LendingIterator for Upper<'t> {
    type Item<'a> = &'a str where Self: 'a;
    fn next(&mut self) -> Option<&str> {
        let line = self.lines.next()?;
        self.buf.clear();
        for c in line.chars() {
            self.buf.extend(c.to_uppercase());
        }
        Some(&self.buf)
    }
}

fn main() {
    let text = "раз\nдва\nтри";
    let mut it = Upper { lines: text.lines(), buf: String::new() };
    while let Some(line) = it.next() {
        println!("{line}");
    }
}
```
```expect
РАЗ
ДВА
ТРИ
```
hint: Возьми строку: `let line = self.lines.next()?;`. Потом `self.buf.clear()` и заполни буфер.
hint: Верни ссылку на буфер: `Some(&self.buf)`. Буфер один на все шаги — копий нет.

:: deep GAT шире итераторов
GAT нужны везде, где ассоциированный тип должен зависеть от параметра: времени жизни или типа.

- **Коллекции-«семейства»**: `type Pointer<T>` — трейт, который говорит «моя умная ссылка — это `Rc<T>`» или «`Arc<T>`», и код пишется для обоих.
- **Асинхронные трейты** до появления `async fn` в трейтах использовали `type Fut<'a>: Future + 'a`.
- **Парсеры без копий**, которые возвращают куски своего буфера.

Обязательное `where Self: 'a` говорит: «ссылка на элемент не переживёт сам итератор». Компилятор требует писать его явно.

:: recap
- GAT: `type Item<'a> where Self: 'a;` — тип элемента зависит от заимствования.
- `LendingIterator` выдаёт ссылки на свой буфер, по одной за раз.
- Используется через `while let`, а не `for`.

## LESSON x02-4 | impl Trait и async fn в трейтах | 8
:: goals
- Возвращать `impl Trait` из методов трейта
- Писать `async fn` прямо в трейте

:: text Возврат impl Trait из метода трейта
В трейте можно написать метод, который возвращает «какой-то итератор» — каждая реализация вернёт свой:

```rust
trait Container {
    fn items(&self) -> impl Iterator<Item = i32>;
}
```
Раньше для этого нужны были `Box<dyn Iterator>` или ассоциированный тип. Теперь — просто `impl`. Это называют **RPITIT** (return-position impl Trait in traits).

:: code
```rust
trait Container {
    fn items(&self) -> impl Iterator<Item = i32>;
    fn total(&self) -> i32 {
        self.items().sum()
    }
}

struct Evens(i32);
struct List(Vec<i32>);

impl Container for Evens {
    fn items(&self) -> impl Iterator<Item = i32> {
        (0..=self.0).filter(|x| x % 2 == 0)
    }
}

impl Container for List {
    fn items(&self) -> impl Iterator<Item = i32> {
        self.0.iter().copied()
    }
}

fn main() {
    println!("{}", Evens(6).total());
    println!("{}", List(vec![5, 5, 1]).total());
}
```
```out
12
11
```
У `Evens` итератор — `Filter<...>`, у `List` — `Copied<...>`. Разные типы, один трейт.

:: text async fn в трейте
Точно так же можно написать `async fn` прямо в трейте:

```rust
trait Storage {
    async fn load(&self, key: &str) -> Option<String>;
}
```
Под капотом это тот же приём: метод возвращает `impl Future<Output = ...>`.

Одна оговорка: такой трейт **не dyn-совместим** (ведь `impl` — это конкретный, но скрытый тип). Для `dyn` используют крейт `async-trait` или ручной `Pin<Box<dyn Future>>`.

:: code
Проверим на самодельной `block_on` из второго уровня:
```rust
use std::future::Future;
use std::pin::pin;
use std::task::{Context, Poll, Waker};

fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut);
    let mut cx = Context::from_waker(Waker::noop());
    loop {
        if let Poll::Ready(v) = fut.as_mut().poll(&mut cx) {
            return v;
        }
    }
}

trait Storage {
    async fn load(&self, key: &str) -> Option<String>;
}

struct Memory;

impl Storage for Memory {
    async fn load(&self, key: &str) -> Option<String> {
        match key {
            "name" => Some(String::from("Ferris")),
            _ => None,
        }
    }
}

async fn greet<S: Storage>(s: &S) -> String {
    let name = s.load("name").await.unwrap_or_default();
    format!("Привет, {name}!")
}

fn main() {
    println!("{}", block_on(greet(&Memory)));
}
```
```out
Привет, Ferris!
```

:: quiz
Можно ли положить в `Vec<Box<dyn Storage>>` типы с `async fn` в трейте?
[ ] Да, без проблем => `async fn` в трейте возвращает скрытый `impl Future`, это не dyn-совместимо.
[x] Нет, для `dyn` нужен `async-trait` или ручной `Pin<Box<dyn Future>>` => Верно.
[ ] Только для `Box`, но не для `&` => Дело не в виде указателя.

Добавь в трейт `Words` метод `long_words(&self, min: usize) -> impl Iterator<Item = &str>`, возвращающий слова длиннее `min` символов. Реализуй его для `Sentence`.
```rust

struct Sentence(String);

// твой код

fn main() {
    let s = Sentence(String::from("мама мыла огромную раму"));
    let v: Vec<&str> = s.long_words(4).collect();
    println!("{v:?}");
}
```
```solution
trait Words {
    fn long_words(&self, min: usize) -> impl Iterator<Item = &str>;
}

struct Sentence(String);

impl Words for Sentence {
    fn long_words(&self, min: usize) -> impl Iterator<Item = &str> {
        self.0.split_whitespace().filter(move |w| w.chars().count() > min)
    }
}

fn main() {
    let s = Sentence(String::from("мама мыла огромную раму"));
    let v: Vec<&str> = s.long_words(4).collect();
    println!("{v:?}");
}
```
```expect
["огромную"]
```
hint: `self.0.split_whitespace().filter(move |w| w.chars().count() > min)`.
hint: `move` нужен, чтобы замыкание забрало `min` с собой.

:: recap
- `fn x(&self) -> impl Trait` прямо в трейте — у каждой реализации свой тип.
- `async fn` в трейте — то же самое, но с `Future`.
- Такие трейты не dyn-совместимы.

```solution
trait Plugin {
    fn create() -> Self
    where
        Self: Sized;
    fn name(&self) -> &str;
    fn run(&self, input: i32) -> i32;
}

struct Double;
struct Inc;

impl Plugin for Double {
    fn create() -> Self { Double }
    fn name(&self) -> &str { "double" }
    fn run(&self, input: i32) -> i32 { input * 2 }
}

impl Plugin for Inc {
    fn create() -> Self { Inc }
    fn name(&self) -> &str { "inc" }
    fn run(&self, input: i32) -> i32 { input + 1 }
}

fn main() {
    let chain: Vec<Box<dyn Plugin>> = vec![Box::new(Double::create()), Box::new(Inc::create())];
    let mut x = 5;
    for p in &chain {
        x = p.run(x);
        println!("{} -> {x}", p.name());
    }
}
```
```expect
double -> 10
inc -> 11
```
hint: `fn create() -> Self where Self: Sized;` — иначе трейт не dyn-совместим.

```rust
use std::any::Any;

struct Click {
    x: i32,
    y: i32,
}
struct Key(char);

fn handle(event: &dyn Any) {
```

```solution
trait LendingIterator {
    type Item<'a>
    where
        Self: 'a;
    fn next(&mut self) -> Option<Self::Item<'_>>;
}

struct ChunksMut<'s> {
    data: &'s mut [i32],
    n: usize,
    pos: usize,
}

impl<'s> LendingIterator for ChunksMut<'s> {
    type Item<'a> = &'a mut [i32] where Self: 'a;
    fn next(&mut self) -> Option<&mut [i32]> {
        if self.pos >= self.data.len() {
            return None;
        }
        let start = self.pos;
        let end = (start + self.n).min(self.data.len());
        self.pos = end;
        Some(&mut self.data[start..end])
    }
}

fn main() {
    let mut v = [1, 2, 3, 4, 5];
    let mut it = ChunksMut { data: &mut v, n: 2, pos: 0 };
    while let Some(c) = it.next() {
        c.reverse();
    }
    println!("{v:?}");
}
```
```expect
[2, 1, 4, 3, 5]
```
hint: Конец куска — `(start + n).min(len)`, чтобы последний кусок не вылез за край.

```solution
trait Source {
    fn numbers(&self) -> impl Iterator<Item = u32>;
    fn max_or_zero(&self) -> u32 {
        self.numbers().max().unwrap_or(0)
    }
}

struct Range10;
struct Fixed(Vec<u32>);

impl Source for Range10 {
    fn numbers(&self) -> impl Iterator<Item = u32> {
        1..=10
    }
}

impl Source for Fixed {
    fn numbers(&self) -> impl Iterator<Item = u32> {
        self.0.iter().copied()
    }
}

fn main() {
    println!("{}", Range10.max_or_zero());
    println!("{}", Fixed(vec![]).max_or_zero());
    println!("{}", Fixed(vec![4, 9, 2]).max_or_zero());
}
```

:: recap
- `where Self: Sized` — конструкторы в dyn-совместимых трейтах.
- `downcast_ref` — разбор разнородных событий.
- GAT позволяет менять данные кусками через свой итератор.
- `impl Iterator` в трейте — гибкие источники данных.
