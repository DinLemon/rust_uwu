# MODULE m18 | Async и макросы | Обзор продвинутых тем

## LESSON m18-1 | Async: ждать, не простаивая | 7
:: goals
- Чем async отличается от потоков
- Что значат `async` и `.await`

:: text Официант, а не повар на каждый стол
Программа часто **ждёт**: ответа от сервера, чтения файла. Пока ждёт — процессор простаивает.

> Потоки — нанять по повару на каждый стол. Async — один официант: принял заказ, отнёс на кухню и, пока блюдо готовится, обслуживает другие столы.

Async выгоден, когда задач очень много, а работы у каждой мало: веб-серверы, чаты, сетевые программы.

:: text async и .await
- `async fn` — функция, которая возвращает не результат, а **обещание** результата (future).
- `.await` — «дождись обещания, а пока дай поработать другим».

```rust
async fn load_user() -> String {
    String::from("Аня")
}

async fn hello() {
    let name = load_user().await;
    println!("Привет, {name}");
}
```

:: text Нужен исполнитель
Future сам по себе ленивый, как итератор. Его кто-то должен «крутить». Это делает **рантайм** — исполнитель.

В стандартной библиотеке рантайма нет. В реальных проектах берут крейт **tokio**:

```text
#[tokio::main]
async fn main() {
    hello().await;
}
```

:: code
Для любопытных: крошечный исполнитель на одной стандартной библиотеке. Понимать каждую строку не нужно.
```rust
use std::future::Future;
use std::pin::pin;
use std::sync::Arc;
use std::task::{Context, Poll, Wake};

struct Noop;
impl Wake for Noop {
    fn wake(self: Arc<Self>) {}
}

fn block_on<F: Future>(fut: F) -> F::Output {
    let waker = Arc::new(Noop).into();
    let mut cx = Context::from_waker(&waker);
    let mut fut = pin!(fut);
    loop {
        if let Poll::Ready(v) = fut.as_mut().poll(&mut cx) {
            return v;
        }
    }
}

async fn load_user() -> String {
    String::from("Аня")
}

async fn hello() -> String {
    let name = load_user().await;
    format!("Привет, {name}")
}

fn main() {
    println!("{}", block_on(hello()));
}
```
```out
Привет, Аня
```

:: quiz
Что произойдёт, если вызвать `async fn` без `.await` и без исполнителя?
[ ] Функция выполнится сразу => Future ленивый: без исполнителя ничего не происходит.
[x] Ничего: создастся future, но он не запустится => Верно. Как итератор без `collect`.
[ ] Программа запаникует => Паники не будет, просто код не выполнится. Компилятор об этом предупредит.

:: recap
- Async — много задач, которые в основном ждут.
- `async fn` возвращает future, `.await` его дожидается.
- Нужен рантайм. В реальных проектах — tokio.

## LESSON m18-2 | Макросы | 6
:: goals
- Чем макрос отличается от функции
- Написать простой макрос `macro_rules!`

:: text Макрос пишет код за тебя
Ты весь курс пользуешься макросами: `println!`, `vec!`, `format!`, `assert_eq!`. Восклицательный знак — их метка.

**Макрос** — это код, который **пишет код** ещё до компиляции. Поэтому `println!` может принять любое количество аргументов, а обычная функция — нет.

:: code
Простой макрос через `macro_rules!`:
```rust
macro_rules! square {
    ($x:expr) => {
        $x * $x
    };
}

macro_rules! hello_all {
    ($($name:expr),*) => {
        $( println!("Привет, {}!", $name); )*
    };
}

fn main() {
    println!("{}", square!(7));
    hello_all!("Аня", "Боря", "Вика");
}
```
```out
49
Привет, Аня!
Привет, Боря!
Привет, Вика!
```
- `$x:expr` — «сюда подставь любое выражение».
- `$(...),*` — «повтори сколько угодно раз через запятую».

:: text derive — тоже макрос
`#[derive(Debug)]` — это **процедурный макрос**. Он читает твою структуру и дописывает к ней реализацию трейта.

Свои процедурные макросы пишут редко. Но знать, что это они, полезно.

:: text unsafe — одна строчка правды
В Rust есть слово `unsafe`. Внутри такого блока можно делать то, что компилятор не может проверить: работать с сырыми указателями, вызывать код на C.

Новичку `unsafe` не нужен. Большинство программ на Rust его вообще не содержат.

:: quiz
Почему `println!` — макрос, а не функция?
[x] Он принимает разное число аргументов и проверяет формат при компиляции => Верно. Обычная функция в Rust так не умеет.
[ ] Макросы работают быстрее функций => Дело не в скорости.
[ ] Так исторически сложилось, разницы нет => Разница есть: макрос раскрывается в код до компиляции.

:: recap
- Макросы с `!` генерируют код до компиляции.
- `macro_rules!` — свои простые макросы.
- `#[derive]` — тоже макрос.
- `unsafe` существует, но новичку не нужен.
