# MODULE m17 | Потоки | Делать несколько дел одновременно

## LESSON m17-1 | Первый поток | 6
:: goals
- Запустить код в отдельном потоке
- Дождаться его через `join`

:: text Поток — ещё один исполнитель
**Поток** (thread) — отдельная линия выполнения. Несколько потоков работают одновременно, на разных ядрах процессора.

> Как несколько поваров на одной кухне. Работа идёт быстрее, но надо договариваться, кто берёт какой нож.

Rust знаменит фразой «бесстрашная многопоточность»: многие ошибки потоков он ловит на компиляции.

:: code
```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..=3 {
            println!("помощник: шаг {i}");
        }
        42
    });
    println!("главный поток ждёт");
    let answer = handle.join().unwrap();
    println!("помощник вернул {answer}");
}
```
- `thread::spawn(замыкание)` — запустить поток.
- `join()` — дождаться его конца и забрать результат.

Порядок строк может меняться от запуска к запуску: потоки идут одновременно.

:: text move — отдать данные потоку
Поток может жить дольше функции, которая его создала. Поэтому одолжить ему переменную нельзя — только **отдать**:

```rust
let name = String::from("Аня");
let h = thread::spawn(move || {
    println!("Привет из потока, {name}");
});
h.join().unwrap();
```
Без `move` будет ошибка `E0373`.

:: quiz
Зачем нужен `join()`?
[ ] Чтобы запустить поток => Запускает `spawn`. `join` — ждёт.
[x] Чтобы дождаться окончания потока => Верно. Иначе `main` может закончиться раньше и прервать поток.
[ ] Чтобы соединить два потока в один => Название сбивает, но нет: это «дождаться».

:: recap
- `thread::spawn(|| ...)` — новый поток.
- `handle.join()` — дождаться и получить результат.
- `move` — отдать потоку переменные.

## LESSON m17-2 | Каналы: потоки пишут друг другу | 6
:: goals
- Передавать данные между потоками через канал

:: text Канал — пневмопочта
**Канал** — труба между потоками. В один конец кладут сообщения, из другого достают.

```rust
let (tx, rx) = mpsc::channel();
```
- `tx` — передатчик (transmitter), им отправляют: `tx.send(x)`.
- `rx` — приёмник (receiver), им получают: `rx.recv()`.

`mpsc` значит «много отправителей, один получатель».

:: code
```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();
    thread::spawn(move || {
        for fruit in ["яблоко", "груша", "слива"] {
            tx.send(fruit).unwrap();
        }
    });
    for got in rx {
        println!("Получил: {got}");
    }
    println!("Канал закрыт");
}
```
```out
Получил: яблоко
Получил: груша
Получил: слива
Канал закрыт
```
Цикл `for got in rx` заканчивается сам, когда передатчик исчезает вместе со своим потоком.

:: quiz
Что передаётся через `send`?
[x] Владение значением => Верно. Отправил — у тебя его больше нет. Так потоки не дерутся за данные.
[ ] Копия значения => Не обязательно копия: значение переезжает.
[ ] Ссылка на значение => Ссылка могла бы повиснуть. Rust отправляет само значение.

:: recap
- `mpsc::channel()` — канал `(tx, rx)`.
- `tx.send(x)` — отправить, `rx.recv()` или `for x in rx` — получить.
- Отправка передаёт владение.

## LESSON m17-3 | Общие данные: Arc и Mutex | 7
:: goals
- Менять одно значение из многих потоков
- Зачем нужны `Arc` и `Mutex`

:: text Замок на двери
`Mutex` (mutual exclusion — взаимное исключение) пускает к данным **по одному**.

> Ключ от туалета в кафе. Взял ключ — зашёл. Остальные ждут, пока вернёшь.

`lock()` берёт ключ. Ключ возвращается сам, когда переменная с ним исчезает.

:: text Arc — Rc для потоков
`Rc` нельзя передавать между потоками: его счётчик не защищён. Для потоков есть `Arc` — **атомарный** Rc.

Классика: `Arc<Mutex<T>>` — общее изменяемое значение для многих потоков.

:: code
```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];
    for _ in 0..10 {
        let c = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            let mut n = c.lock().unwrap();
            *n += 1;
        }));
    }
    for h in handles {
        h.join().unwrap();
    }
    println!("Итог: {}", *counter.lock().unwrap());
}
```
```out
Итог: 10
```
Десять потоков, каждый прибавил 1. Без Mutex результат мог бы быть меньше: потоки затирали бы друг друга.

:: text thread::scope — проще для коротких задач
Если потоки нужны только внутри одного блока, `thread::scope` разрешает им **одалживать** данные. `move` и `Arc` не нужны:

```rust
let data = vec![1, 2, 3, 4];
let (left, right) = data.split_at(2);
thread::scope(|s| {
    s.spawn(|| println!("{}", left.iter().sum::<i32>()));
    s.spawn(|| println!("{}", right.iter().sum::<i32>()));
});
```

:: quiz
Почему для потоков нужен `Arc`, а не `Rc`?
[ ] `Arc` быстрее => Наоборот, чуть медленнее. Зато безопасен.
[x] Счётчик `Arc` безопасно меняется из разных потоков => Верно. Компилятор не даст отправить `Rc` в поток.
[ ] `Rc` нельзя клонировать => Можно, но только в одном потоке.

:: recap
- `Mutex` — доступ по одному, `lock()` — взять ключ.
- `Arc` — общий владелец для потоков.
- `Arc<Mutex<T>>` — общие изменяемые данные.
- `thread::scope` — потоки, которые одалживают данные.
