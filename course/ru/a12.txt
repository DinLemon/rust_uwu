# MODULE a12 | Скорость и инструменты | Измерять, меньше выделять память, clippy, документация и свой крейт

## LESSON a12-1 | Сначала измерь | 7
:: goals
- Измерять время кусочка кода
- Помнить про `--release` и `black_box`

:: text Главное правило скорости
Не угадывай, где медленно. **Измеряй.** Программисты постоянно ошибаются, думая, где «тормозит». Часто это совсем не то место.

> **Аналогия:** врач не лечит «на глаз». Сначала анализы, потом таблетки.

:: text Debug и release
Rust собирает программу двумя способами:
- `cargo run` — **debug**: быстро собирается, много проверок, медленно работает.
- `cargo run --release` — **release**: собирается дольше, работает в разы (иногда в десятки раз) быстрее.

Измерять скорость имеет смысл **только** в release. В Playground переключатель называется **Debug / Release** — слева вверху.

:: code
`std::time::Instant` — секундомер:
```rust
use std::time::Instant;

fn slow_sum(n: u64) -> u64 {
    let mut s = 0;
    for i in 0..n {
        s += i % 7;
    }
    s
}

fn main() {
    let start = Instant::now();
    let r = slow_sum(10_000_000);
    let took = start.elapsed();
    println!("результат {r}, заняло {took:?}");
}
```
Время будет разным при каждом запуске. Попробуй переключить Playground в **Release** и сравни.

:: text Ловушка: компилятор слишком умный
В release компилятор может **выкинуть** вычисление, если результат никто не использует. Или посчитать его заранее. Тогда замер покажет ноль.

`std::hint::black_box(x)` говорит компилятору: «не трогай, считай по-честному».

```rust
use std::hint::black_box;
let r = slow_sum(black_box(10_000_000));
```

:: text Инструменты для серьёзных замеров
- **criterion** (крейт) — много раз запускает код, считает среднее и разброс, рисует графики. Стандарт для бенчмарков.
- **flamegraph** (`cargo flamegraph`) — картинка «где программа проводит время». Широкий столбик — горячее место.

:: quiz
Ты замерил скорость в режиме debug, и вышло медленно. Что делать сначала?
[ ] Переписать всё на unsafe => Рано. Сначала проверь в release.
[x] Замерить ещё раз в release => Верно. В debug замеры почти бессмысленны.
[ ] Добавить потоки => Сначала нужно понять, где медленно.

:: recap
- Сначала измерь, потом ускоряй.
- Замеры — только в release.
- `Instant::now()` + `elapsed()`, `black_box` против «умного» компилятора.

## LESSON a12-2 | Меньше выделений памяти | 8
:: goals
- Знать, что выделение памяти в куче — дорогая операция
- Использовать `with_capacity`, `&str` и переиспользование буферов

:: text Выделение — это поход на склад
Каждый `String::new()` с данными, `Vec::push` сверх места, `clone()` — это просьба к системе «дай памяти». Это **медленнее**, чем арифметика, в десятки и сотни раз.

Частые источники лишних выделений:
- `Vec`, который растёт по одному элементу;
- `clone()` там, где хватило бы ссылки;
- `format!` и `to_string()` в горячем цикле.

> **Аналогия:** каждый раз ходить на склад за одной тарелкой. Лучше сразу взять стопку.

:: code
`Vec` растёт, удваивая место. `with_capacity` выделяет сразу сколько нужно:
```rust
fn main() {
    let mut a = Vec::new();
    let mut grows = 0;
    let mut cap = a.capacity();
    for i in 0..1000 {
        a.push(i);
        if a.capacity() != cap {
            grows += 1;
            cap = a.capacity();
        }
    }
    println!("без with_capacity: {grows} переездов");

    let mut b = Vec::with_capacity(1000);
    let before = b.capacity();
    for i in 0..1000 {
        b.push(i);
    }
    println!("с with_capacity: {} переездов", if b.capacity() == before { 0 } else { 1 });
}
```
```out
без with_capacity: 9 переездов
с with_capacity: 0 переездов
```
Каждый «переезд» — новое выделение и копирование всех элементов.

:: text Ссылка вместо копии
Функция, которая только **читает** строку, должна брать `&str`, а не `String`:

```rust
fn count_a(s: &str) -> usize { s.matches('a').count() } // хорошо
fn count_a(s: String) -> usize { ... }                   // заставит клонировать
```
`&str` подходит и для `String` (через `&s`), и для литералов. Это и гибче, и быстрее.

:: text Один буфер на много раз
Если в цикле нужна временная строка или вектор, создай его **один раз** перед циклом и очищай через `clear()`. `clear()` оставляет выделенную память — следующему шагу не придётся просить её заново.

```rust
let mut line = String::new();
for item in items {
    line.clear();
    line.push_str(item.name());
    // ...
}
```

:: quiz
Ты заранее знаешь, что в вектор попадёт 10 000 элементов. Как его создать?
[ ] `Vec::new()` => Будет много переездов по мере роста.
[x] `Vec::with_capacity(10_000)` => Верно. Одно выделение на всё.
[ ] `vec![0; 10_000]` и потом `push` => Тогда в нём будет 20 000 элементов.

:: task
Функция `join_upper` собирает слова в одну строку через пробел в верхнем регистре. Сделай так, чтобы строка-результат создавалась **один раз** с нужной ёмкостью, без `format!` в цикле.
```rust
fn join_upper(words: &[&str]) -> String {
    let mut out = String::new();
    for w in words {
        out = format!("{out}{} ", w.to_uppercase());
    }
    out.trim_end().to_string()
}

fn main() {
    println!("{}", join_upper(&["rust", "is", "fast"]));
}
```
```solution
fn join_upper(words: &[&str]) -> String {
    let total: usize = words.iter().map(|w| w.len() + 1).sum();
    let mut out = String::with_capacity(total);
    for (i, w) in words.iter().enumerate() {
        if i > 0 {
            out.push(' ');
        }
        for c in w.chars() {
            out.extend(c.to_uppercase());
        }
    }
    out
}

fn main() {
    println!("{}", join_upper(&["rust", "is", "fast"]));
}
```
```expect
RUST IS FAST
```
contains: with_capacity
hint: Сначала посчитай длину: сумма длин слов плюс пробелы. Потом `String::with_capacity(total)`.
hint: Внутри цикла добавляй через `push(' ')` и `push_str` (или `extend` для символов).

:: recap
- Выделение памяти дорогое. Меньше выделений — быстрее.
- `with_capacity`, если размер известен заранее.
- Читаешь — бери `&str`/`&[T]`. Временный буфер — один на цикл, `clear()`.

## LESSON a12-3 | clippy, rustfmt и документация | 7
:: goals
- Знать три инструмента, которые есть у каждого Rust-программиста
- Писать документацию с примерами, которые проверяются

:: text rustfmt — единый стиль
`cargo fmt` расставляет отступы, переносы и пробелы по общему стилю. Не надо спорить о красоте: у всех одинаково.

В Playground: **Tools → Rustfmt**.

:: text clippy — внимательный помощник
`cargo clippy` знает сотни советов: «тут можно проще», «тут лишний clone», «тут возможная ошибка».

```rust
if x == true { ... }        // clippy: пиши просто `if x`
let v = vec.len() == 0;     // clippy: есть `vec.is_empty()`
for i in 0..v.len() { v[i] } // clippy: лучше `for x in &v`
```
В Playground: **Tools → Clippy**.

> **Аналогия:** rustfmt — корректор, который выравнивает текст. clippy — редактор, который говорит «эту фразу можно сказать проще».

:: text Документация — тоже код
Комментарий `///` над функцией — это документация. `cargo doc --open` превращает её в красивый сайт, как на docs.rs.

```rust
/// Удваивает число.
///
/// # Пример
/// ```
/// assert_eq!(mylib::double(4), 8);
/// ```
pub fn double(x: i32) -> i32 { x * 2 }
```
Пример внутри ```` ``` ```` **запускается** командой `cargo test`. Документация не врёт: устаревший пример сломает тесты.

:: text Принятые разделы
В документации часто бывают заголовки:
- `# Examples` — примеры использования;
- `# Errors` — когда функция возвращает `Err`;
- `# Panics` — когда она паникует;
- `# Safety` — для `unsafe fn`: что обязан гарантировать вызывающий.

`//!` в начале файла — документация всего модуля или крейта.

:: quiz
Что произойдёт с примером кода в комментарии `///` при `cargo test`?
[ ] Ничего, это просто текст => Это не просто текст.
[x] Он скомпилируется и запустится как тест => Верно. Это doc-тест.
[ ] Он будет напечатан в консоль => Нет, он выполняется как тест.

:: quiz
Какая команда подскажет, что `if x == true` можно написать проще?
[ ] `cargo fmt` => Он только расставляет пробелы и переносы.
[x] `cargo clippy` => Верно.
[ ] `cargo doc` => Он строит документацию.

:: recap
- `cargo fmt` — единый стиль.
- `cargo clippy` — советы и найденные ошибки.
- `///` — документация, примеры в ней — тесты.

## LESSON a12-4 | Свой крейт | 7
:: goals
- Понять, из чего состоит крейт и как его выпускают
- Знать про семантические версии и features

:: text Cargo.toml поближе
```toml
[package]
name = "tiny-calc"
version = "0.1.0"
edition = "2024"
description = "Маленький калькулятор"
license = "MIT"

[dependencies]
serde = { version = "1", features = ["derive"] }
```
`description` и `license` обязательны, чтобы опубликовать крейт на crates.io.

:: text Семантические версии
Версия `MAJOR.MINOR.PATCH`, например `1.4.2`:
- `PATCH` (1.4.**3**) — исправили ошибку, ничего не сломали;
- `MINOR` (1.**5**.0) — добавили новое, старое работает;
- `MAJOR` (**2**.0.0) — что-то сломали, пользователям придётся менять код.

Когда пишешь `serde = "1"`, Cargo возьмёт самую свежую `1.x.y`, но не `2.0`. Так обновления не ломают твой проект.

> **Аналогия:** PATCH — пришили пуговицу. MINOR — добавили карман. MAJOR — перешили пиджак в жилет.

:: text Features — включаемые части
Крейт может иметь необязательные куски, которые включаются по желанию:

```toml
[features]
default = []
json = ["dep:serde_json"]
```
В коде:
```rust
#[cfg(feature = "json")]
pub fn to_json(...) { ... }
```
Пользователь пишет `tiny-calc = { version = "0.1", features = ["json"] }` и получает функцию. Не нужно — не платит за лишние зависимости.

:: text Как опубликовать
1. Войти на crates.io через GitHub и получить токен.
2. `cargo login` — сохранить токен.
3. `cargo publish --dry-run` — проверить, что всё собирается.
4. `cargo publish` — выпустить.

Опубликованную версию **нельзя удалить**, только пометить устаревшей (`cargo yank`). Поэтому проверяй перед выпуском.

:: text Workspace — несколько крейтов вместе
Большой проект часто делят на крейты: `core`, `cli`, `web`. Они лежат в одной папке и собираются вместе:

```toml
# Cargo.toml в корне
[workspace]
members = ["core", "cli"]
```
Общий `Cargo.lock`, общая папка `target`, одна команда `cargo test` проверяет всё.

:: quiz
Ты добавил в библиотеку новую функцию, а старые не трогал. Какую часть версии поднять?
[ ] MAJOR => Ничего не сломалось, MAJOR не нужен.
[x] MINOR => Верно. Новое добавилось, старое работает.
[ ] PATCH => PATCH — для исправлений без новых возможностей.

:: quiz
Что делает `features = ["json"]` в зависимости?
[x] Включает необязательную часть крейта под названием `json` => Верно.
[ ] Конвертирует крейт в JSON => Нет, это просто имя части крейта.
[ ] Ускоряет сборку => Скорее наоборот: включает больше кода.

:: recap
- `Cargo.toml`: имя, версия, лицензия, зависимости.
- Версии: PATCH — исправление, MINOR — новое, MAJOR — ломающее.
- Features — части по выбору. `cargo publish` — выпуск, удалить нельзя.

## LESSON a12-p | Практика: скорость и стиль | 12 | practice
:: goals
- Исправить типичные «медленные» и «некрасивые» места

:: task
clippy ругается на этот код в трёх местах. Перепиши: `is_empty()` вместо сравнения длины, `for x in &v` вместо индексов и без `== true`.
```rust
fn main() {
    let v = vec![3, 1, 4];
    let mut sum = 0;
    for i in 0..v.len() {
        sum += v[i];
    }
    let empty = v.len() == 0;
    if empty == false {
        println!("сумма {sum}");
    }
}
```
```solution
fn main() {
    let v = vec![3, 1, 4];
    let mut sum = 0;
    for x in &v {
        sum += x;
    }
    let empty = v.is_empty();
    if !empty {
        println!("сумма {sum}");
    }
}
```
```expect
сумма 8
```
contains: is_empty()
hint: `for x in &v { sum += x; }`.
hint: `v.is_empty()` и `if !empty`.

:: task
Функция `longest_len` принимает `Vec<String>` и из-за этого заставляет вызывающего клонировать. Сделай так, чтобы она брала срез `&[String]`, и убери `clone()` в `main`.
```rust
fn longest_len(words: Vec<String>) -> usize {
    words.iter().map(|w| w.chars().count()).max().unwrap_or(0)
}

fn main() {
    let words = vec![String::from("краб"), String::from("ржавчина")];
    println!("{}", longest_len(words.clone()));
    println!("слов: {}", words.len());
}
```
```solution
fn longest_len(words: &[String]) -> usize {
    words.iter().map(|w| w.chars().count()).max().unwrap_or(0)
}

fn main() {
    let words = vec![String::from("краб"), String::from("ржавчина")];
    println!("{}", longest_len(&words));
    println!("слов: {}", words.len());
}
```
```expect
8
слов: 2
```
hint: Сигнатура: `fn longest_len(words: &[String]) -> usize`. Вызов: `longest_len(&words)`.

:: task
Собери строки из чисел `1..=5` в формате `"1-2-3-4-5"`, используя один буфер `String::with_capacity` и `push_str`. Без `format!` в цикле.
```rust
fn main() {
    // твой код
}
```
```solution
fn main() {
    let mut out = String::with_capacity(16);
    for i in 1..=5 {
        if i > 1 {
            out.push('-');
        }
        out.push_str(&i.to_string());
    }
    println!("{out}");
}
```
```expect
1-2-3-4-5
```
contains: with_capacity
hint: `let mut out = String::with_capacity(16);` — места хватит с запасом.
hint: Перед каждым числом, кроме первого, `out.push('-')`.

:: recap
- clippy учит писать проще и правильнее.
- Принимай срезы, а не владеющие типы, если только читаешь.
- Буфер с запасом + `push_str` вместо `format!` в цикле.
