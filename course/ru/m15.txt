# MODULE m15 | Тесты | Как убедиться, что код работает

## LESSON m15-1 | Первый тест | 6
:: goals
- Написать тест с `#[test]`
- Проверять результат через `assert_eq!`

:: text Тест — автоматическая проверка
**Тест** — маленькая функция, которая проверяет другую функцию. Написал один раз — проверяешь хоть тысячу раз, одной командой.

> Как чек-лист пилота перед взлётом. Скучно, но спасает.

:: text Как выглядит тест
```rust
#[test]
fn two_plus_two() {
    assert_eq!(add(2, 2), 4);
}
```
- `#[test]` — «это тест».
- `assert_eq!(a, b)` — «a должно равняться b». Не равно — тест провален.
- `assert!(условие)` — «условие должно быть правдой».

:: code
Здесь нет `main`. Кнопка «Запустить» прогонит тесты.
```rust
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_positive() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn adds_negative() {
        assert_eq!(add(-2, -3), -5);
    }
}
```
tests: yes
В выводе будет `test result: ok. 2 passed`. Поменяй `a + b` на `a - b` и запусти снова: увидишь провал и что именно не совпало.

:: text Что за mod tests
- `#[cfg(test)]` — «собирать этот модуль только при тестах». В готовую программу он не попадёт.
- `use super::*;` — «взять всё из модуля выше». Иначе тесты не увидят `add`.

На своём компьютере тесты запускают командой `cargo test`.

:: quiz
Что делает `assert_eq!(x, 10)`?
[ ] Присваивает `x` значение 10 => Это проверка, а не присваивание.
[x] Проваливает тест, если `x` не равен 10 => Верно.
[ ] Печатает `x` => Печатает только при провале, чтобы показать разницу.

:: recap
- `#[test] fn имя() { ... }` — тест.
- `assert_eq!(a, b)`, `assert!(условие)` — проверки.
- Тесты кладут в `#[cfg(test)] mod tests`, запускают `cargo test`.

## LESSON m15-2 | Тесты на ошибки | 6
:: goals
- Проверить, что функция паникует
- Проверять `Result` в тестах

:: text should_panic
Иногда правильное поведение — паника. Это проверяют атрибутом `#[should_panic]`:

```rust
#[test]
#[should_panic]
fn divide_by_zero_panics() {
    divide(1, 0);
}
```

:: text Тест может вернуть Result
Тогда внутри можно использовать `?`. Ошибка = провал теста.

```rust
#[test]
fn parses() -> Result<(), std::num::ParseIntError> {
    let n: i32 = "42".parse()?;
    assert_eq!(n, 42);
    Ok(())
}
```

:: task
Напиши функцию `is_adult(age: u32) -> bool` (взрослый — от 18) и два теста к ней: для 20 и для 10.
```rust
pub fn is_adult(age: u32) -> bool {
    // твой код
}

#[cfg(test)]
mod tests {
    use super::*;

    // твои тесты
}
```
```solution
pub fn is_adult(age: u32) -> bool {
    age >= 18
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn twenty_is_adult() {
        assert!(is_adult(20));
    }

    #[test]
    fn ten_is_not_adult() {
        assert!(!is_adult(10));
    }
}
```
tests: yes
contains: #[test]
hint: Тело функции — одно выражение: `age >= 18`.
hint: Тест: `#[test] fn twenty() { assert!(is_adult(20)); }`. Для 10 — `assert!(!is_adult(10));`
explain: Тесты прошли. Так и пишут надёжные программы: функция + проверки.

:: recap
- `#[should_panic]` — тест ждёт панику.
- Тест может вернуть `Result` и использовать `?`.
- Пиши тесты на обычные случаи и на граничные: 0, пусто, очень много.
