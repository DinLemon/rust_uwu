# MODULE m15 | Тесты | Как убедиться, что код работает

## LESSON m15-1 | Первый тест | 6
:: goals
- Написать тест с `#[test]`
- Проверять результат через `assert_eq!`

:: text Тест — автоматическая проверка
**Тест** — маленькая функция, которая проверяет другую функцию. Написал один раз — проверяешь хоть тысячу раз, одной командой.

> **Аналогия:** это как чек-лист пилота перед взлётом. Скучно, но спасает.

:: text Как выглядит тест
```rust
#[test]
fn two_plus_two() {
    assert_eq!(add(2, 2), 4);
}
```
- `#[test]` — «это тест».
- `assert_eq!(a, b)` — «a должно равняться b». Не равно — тест провален.
- `assert!(условие)` — «условие должно быть правдой».

:: code
Здесь нет `main`. Кнопка «Запустить» прогонит тесты.
```rust
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_positive() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn adds_negative() {
        assert_eq!(add(-2, -3), -5);
    }
}
```
tests: yes
В выводе будет `test result: ok. 2 passed`. Поменяй `a + b` на `a - b` и запусти снова: увидишь провал и что именно не совпало.

:: text Что за mod tests
- `#[cfg(test)]` — «собирать этот модуль только при тестах». В готовую программу он не попадёт.
- `use super::*;` — «взять всё из модуля выше». Иначе тесты не увидят `add`.

На своём компьютере тесты запускают командой `cargo test`.

:: quiz
Что делает `assert_eq!(x, 10)`?
[ ] Присваивает `x` значение 10 => Это проверка, а не присваивание.
[x] Проваливает тест, если `x` не равен 10 => Верно.
[ ] Печатает `x` => Печатает только при провале, чтобы показать разницу.

:: text Ещё проверки и свои сообщения
- `assert_ne!(a, b)` — «a **не** должно равняться b».
- К любой проверке можно добавить своё сообщение. Оно появится при провале:

```rust
assert!(age >= 18, "возраст {age} меньше 18");
assert_eq!(total, 100, "сумма должна быть 100");
```
Хорошее сообщение экономит время: сразу видно, что пошло не так.

:: recap
- `#[test] fn имя() { ... }` — тест.
- `assert_eq!(a, b)`, `assert!(условие)` — проверки.
- Тесты кладут в `#[cfg(test)] mod tests`, запускают `cargo test`.

## LESSON m15-2 | Тесты на ошибки | 6
:: goals
- Проверить, что функция паникует
- Проверять `Result` в тестах

:: text should_panic
Иногда правильное поведение — паника. Это проверяют атрибутом `#[should_panic]`:

```rust
#[test]
#[should_panic]
fn divide_by_zero_panics() {
    divide(1, 0);
}
```

:: text Тест может вернуть Result
Тогда внутри можно использовать `?`. Ошибка = провал теста.

```rust
#[test]
fn parses() -> Result<(), std::num::ParseIntError> {
    let n: i32 = "42".parse()?;
    assert_eq!(n, 42);
    Ok(())
}
```

:: task
Напиши функцию `is_adult(age: u32) -> bool` (взрослый — от 18) и два теста к ней: для 20 и для 10.
```rust
pub fn is_adult(age: u32) -> bool {
    // твой код
}

#[cfg(test)]
mod tests {
    use super::*;

    // твои тесты
}
```
```solution
pub fn is_adult(age: u32) -> bool {
    age >= 18
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn twenty_is_adult() {
        assert!(is_adult(20));
    }

    #[test]
    fn ten_is_not_adult() {
        assert!(!is_adult(10));
    }
}
```
tests: yes
contains: #[test]
hint: Тело функции — одно выражение: `age >= 18`.
hint: Тест: `#[test] fn twenty() { assert!(is_adult(20)); }`. Для 10 — `assert!(!is_adult(10));`
explain: Тесты прошли. Так и пишут надёжные программы: функция + проверки.

:: deep Тесты в документации и папка tests
В Rust есть ещё два вида тестов.

**Документирующие тесты.** Пример кода в комментарии `///` тоже запускается командой `cargo test`. Так документация никогда не устаревает:

```rust
/// Удваивает число.
///
/// ```
/// assert_eq!(my_crate::double(2), 4);
/// ```
pub fn double(x: i32) -> i32 { x * 2 }
```

**Интеграционные тесты.** Файлы в папке `tests/` рядом с `src/`. Они видят библиотеку так же, как её будут видеть другие программы: только публичные функции.

Итого: модульные тесты (`mod tests`) проверяют детали, интеграционные — работу целиком, документирующие — что примеры верны.

:: recap
- `#[should_panic]` — тест ждёт панику.
- Тест может вернуть `Result` и использовать `?`.
- Пиши тесты на обычные случаи и на граничные: 0, пусто, очень много.

```rust
pub fn max_of(items: &[i32]) -> i32 {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

#[cfg(test)]
mod tests {
    use super::*;
}
```
```solution
pub fn max_of(items: &[i32]) -> i32 {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn positive() {
        assert_eq!(max_of(&[3, 9, 2]), 9);

    #[test]
    fn negative() {
        assert_eq!(max_of(&[-5, -1]), -1);

:: task
Тесты уже написаны, но функция с ошибкой. Найди ошибку по сообщению о провале и почини функцию.
```rust
pub fn average(items: &[f64]) -> f64 {
    let mut sum = 0.0;
    for x in items {
        sum += x;
    }
    sum / 2.0
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn three_items() {
        assert_eq!(average(&[1.0, 2.0, 6.0]), 3.0);
    }

    #[test]
    fn two_items() {
        assert_eq!(average(&[4.0, 6.0]), 5.0);
    }
}
```
```solution
pub fn average(items: &[f64]) -> f64 {
    let mut sum = 0.0;
    for x in items {
        sum += x;
    }
    sum / items.len() as f64
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn three_items() {
        assert_eq!(average(&[1.0, 2.0, 6.0]), 3.0);
    }

    #[test]
    fn two_items() {
        assert_eq!(average(&[4.0, 6.0]), 5.0);
    }
}
```
tests: yes
hint: Тест с двумя числами проходит, а с тремя — нет. Что в функции работает только для двух чисел?
hint: Делить нужно на количество: `sum / items.len() as f64`.

:: task
Функция `first_char` паникует на пустой строке. Напиши тест с `#[should_panic]`, который это проверяет.
```rust
pub fn first_char(s: &str) -> char {
    s.chars().next().expect("пустая строка")
}

#[cfg(test)]
mod tests {
    use super::*;
}
```
```solution
pub fn first_char(s: &str) -> char {
    s.chars().next().expect("пустая строка")
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    #[should_panic]
    fn empty_panics() {
        first_char("");
    }
}
```
tests: yes
contains: should_panic
hint: Два атрибута подряд: `#[test]` и `#[should_panic]`.
hint: Внутри теста просто вызови `first_char("");`

:: quiz
Тест упал с сообщением `left: 4, right: 5`. Что это значит?
[x] Функция вернула 4, а тест ожидал 5 => Верно. `left` — первое значение в `assert_eq!`, `right` — второе.
[ ] В тесте 4 ошибки из 5 => Это не количество ошибок, а два сравниваемых значения.
[ ] Тест запускался 4 раза => Числа — это значения, которые не совпали.

:: recap
- Тесты пишут рядом с кодом, в `#[cfg(test)] mod tests`.
- Сообщение о провале показывает `left` и `right` — с ним ошибку найти проще.
- `#[should_panic]` проверяет, что паника случилась.
