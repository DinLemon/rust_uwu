# MODULE a11 | unsafe и FFI | Сырые указатели, безопасные обёртки и разговор с C

## LESSON a11-1 | Что разрешает unsafe | 8
:: goals
- Понять, что `unsafe` не отключает проверки, а даёт пять дополнительных возможностей
- Поработать с сырыми указателями

:: text unsafe — не «без правил»
Компилятор Rust осторожный: если он не может **доказать**, что код безопасен, он его не пропустит. Но иногда безопасный код всё равно не доказать — например, работу с железом или с библиотекой на C.

Блок `unsafe { ... }` говорит: «здесь я сам отвечаю за безопасность». Проверки заимствования и типов **продолжают работать**. Добавляются только пять «суперсил»:
1. разыменовать **сырой указатель**;
2. вызвать `unsafe`-функцию;
3. читать/менять изменяемую статическую переменную;
4. реализовать `unsafe`-трейт (например, `Send` вручную);
5. обращаться к полям `union`.

> **Аналогия:** табличка «Только для персонала». За дверью те же правила техники безопасности, но открывать её можно только тем, кто знает, что делает.

:: text Сырые указатели
`*const T` и `*mut T` — указатели «как в C». В отличие от ссылок:
- могут быть нулевыми или указывать на мусор;
- компилятор не следит, сколько их и кто меняет данные;
- создавать их можно где угодно, а **разыменовывать** — только в `unsafe`.

```rust
let x = 5;
let p = &raw const x; // создать — безопасно
let v = unsafe { *p }; // прочитать — только в unsafe
```

:: code
```rust
fn main() {
    let mut nums = [10, 20, 30];
    let p = nums.as_mut_ptr(); // *mut i32 на первый элемент

    unsafe {
        *p.add(1) += 5;           // второй элемент
        let third = *p.add(2);    // третий
        println!("третий: {third}");
    }
    println!("{nums:?}");
}
```
```out
третий: 30
[10, 25, 30]
```
`p.add(1)` — сдвинуть указатель на один элемент. Если сдвинуть за край массива и прочитать — это **неопределённое поведение**: программа может сделать что угодно. Отвечаешь за это ты.

:: quiz
Что происходит с проверкой заимствований внутри `unsafe`-блока?
[ ] Отключается => Нет, она работает как обычно.
[x] Работает как обычно, просто добавляются пять возможностей => Верно.
[ ] Работает только для ссылок `&mut` => Работает для всех ссылок.

:: quiz
Где можно **создать** сырой указатель, а где **прочитать** по нему?
[x] Создать — где угодно, прочитать — только в `unsafe` => Верно. Опасно именно чтение и запись.
[ ] И то, и другое — только в `unsafe` => Создание указателя само по себе ничего не ломает.
[ ] И то, и другое — где угодно => Тогда `unsafe` был бы не нужен.

:: deep Что такое неопределённое поведение
**Неопределённое поведение** (undefined behavior, UB) — ситуация, про которую язык ничего не обещает. Чтение за краем массива, две `&mut` на одно и то же, чтение неинициализированной памяти.

Опасность в том, что программа может **казаться** рабочей. Компилятор при оптимизации считает, что UB никогда не бывает, и может переставить или выкинуть код. Ошибка вылезет потом, в другом месте, на другом компьютере.

Безопасный Rust гарантирует: UB нет. В `unsafe` гарантию даёшь ты сам.

:: recap
- `unsafe` = «за безопасность отвечаю я». Проверки не выключаются.
- Пять суперсил, главная — разыменовать сырой указатель.
- Ошибка в `unsafe` может дать неопределённое поведение.

## LESSON a11-2 | Безопасная обёртка | 8
:: goals
- Спрятать `unsafe` внутри функции с безопасным интерфейсом
- Писать комментарий `// SAFETY:` с объяснением

:: text Главная идея
Стандартная библиотека полна `unsafe`: `Vec`, `String`, `HashMap` внутри работают с сырыми указателями. Но снаружи они **безопасные**: как ни вызывай — UB не будет.

Это и есть правильный подход: маленький кусок `unsafe` **внутри**, вокруг него проверки, а наружу — обычная безопасная функция.

> **Аналогия:** электрощиток. Внутри опасные провода, но снаружи — крышка и выключатели. Пользуется любой, а под крышку лезет электрик.

:: code
Своя версия `split_at_mut`: два **разных** изменяемых куска одного среза. Обычными ссылками компилятор такое не разрешит, хотя куски не пересекаются.
```rust
fn split_mut(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
    assert!(mid <= v.len(), "mid за пределами среза");
    let len = v.len();
    let p = v.as_mut_ptr();
    // SAFETY: mid <= len проверено выше, поэтому оба куска внутри среза
    // и не пересекаются: [0, mid) и [mid, len).
    unsafe {
        (
            std::slice::from_raw_parts_mut(p, mid),
            std::slice::from_raw_parts_mut(p.add(mid), len - mid),
        )
    }
}

fn main() {
    let mut data = [1, 2, 3, 4, 5];
    let (a, b) = split_mut(&mut data, 2);
    a[0] = 100;
    b[0] = 300;
    println!("{data:?}");
}
```
```out
[100, 2, 300, 4, 5]
```
`assert!` — это и есть «проверка вокруг». Без неё вызов `split_mut(&mut data, 99)` дал бы UB. С ней — честную панику.

:: text Комментарий SAFETY
Перед каждым `unsafe`-блоком принято писать, **почему** он безопасен:

```rust
// SAFETY: индекс проверен выше, i < len
unsafe { *ptr.add(i) }
```
А у `unsafe fn` — раздел `# Safety` в документации: что должен гарантировать тот, кто её вызывает. Линтер `clippy` умеет требовать такие комментарии.

:: quiz
Что главное в безопасной обёртке над `unsafe`?
[ ] Чтобы `unsafe` было как можно больше => Наоборот, как можно меньше.
[x] Что бы ни передали в функцию, UB случиться не может => Верно. Все опасные случаи отсекаются проверками.
[ ] Чтобы функция называлась `safe_...` => Название ничего не гарантирует.

:: task
Функция `get_two` возвращает элементы с индексами `i` и `j` (сумму). Внутри используется `get_unchecked`. Добавь проверку, чтобы при плохих индексах была паника `индекс вне среза`, а не UB.
```rust
fn get_two(v: &[i32], i: usize, j: usize) -> i32 {
    // добавь проверку
    // SAFETY: i и j проверены выше и меньше v.len()
    unsafe { v.get_unchecked(i) + v.get_unchecked(j) }
}

fn main() {
    let v = [5, 10, 20];
    println!("{}", get_two(&v, 0, 2));
}
```
```solution
fn get_two(v: &[i32], i: usize, j: usize) -> i32 {
    assert!(i < v.len() && j < v.len(), "индекс вне среза");
    // SAFETY: i и j проверены выше и меньше v.len()
    unsafe { v.get_unchecked(i) + v.get_unchecked(j) }
}

fn main() {
    let v = [5, 10, 20];
    println!("{}", get_two(&v, 0, 2));
}
```
```expect
25
```
contains: assert!
hint: `assert!(i < v.len() && j < v.len(), "индекс вне среза");`.

:: deep Miri — проверка unsafe-кода
**Miri** — интерпретатор Rust, который выполняет программу очень медленно, но **замечает** UB: выход за границы, неправильные указатели, нарушения правил заимствования.

```
rustup +nightly component add miri
cargo +nightly miri test
```
Если пишешь `unsafe`, прогоняй тесты через Miri. В Rust Playground он тоже есть: **Tools → Miri**.

:: recap
- `unsafe` прячут внутри безопасной функции.
- Проверки (`assert!`) отсекают все опасные входы.
- `// SAFETY:` — объяснение, почему блок безопасен.

## LESSON a11-3 | FFI: разговор с C | 8
:: goals
- Вызвать функцию из библиотеки на C
- Сделать функцию на Rust, которую сможет вызвать C

:: text Зачем это нужно
Огромное количество библиотек написано на C: работа с системой, графика, сжатие, базы данных. Rust умеет вызывать их напрямую. Это называют **FFI** (foreign function interface, «интерфейс к чужим функциям»).

Rust не может проверить, что внутри C-функции всё правильно. Поэтому каждый такой вызов — `unsafe`.

> **Аналогия:** звонок в другую страну. Связь есть, но за качество разговора на той стороне твой оператор не отвечает.

:: code
```rust
use std::ffi::{CStr, CString};
use std::os::raw::{c_char, c_int};

unsafe extern "C" {
    fn abs(x: c_int) -> c_int;
    fn strlen(s: *const c_char) -> usize;
}

fn main() {
    let a = unsafe { abs(-42) };
    println!("abs: {a}");

    let text = CString::new("привет").unwrap();
    let n = unsafe { strlen(text.as_ptr()) };
    println!("байт: {n}");

    let back: &CStr = text.as_c_str();
    println!("обратно: {}", back.to_str().unwrap());
}
```
```out
abs: 42
байт: 12
обратно: привет
```
`unsafe extern "C" { ... }` — объявление: «такие функции где-то есть, у них соглашение вызова C». Rust верит на слово.

:: text Строки на границе
Строки в C и Rust устроены по-разному:
- в C строка — указатель на байты, которые заканчиваются **нулевым байтом** `\0`;
- в Rust `String` знает свою длину и нуля в конце нет.

Поэтому есть переходники:
- `CString` — своя строка «как в C» (с нулём в конце). `.as_ptr()` даёт `*const c_char`.
- `CStr` — ссылка на чужую C-строку.

:: text Rust для C
Можно и наоборот — сделать функцию, которую вызовет C:

```rust
#[unsafe(no_mangle)]
pub extern "C" fn add_numbers(a: i32, b: i32) -> i32 {
    a + b
}
```
- `extern "C"` — использовать соглашение вызова C;
- `#[unsafe(no_mangle)]` — оставить имя `add_numbers` как есть (обычно Rust его «перемешивает»).

Так пишут модули для Python, Node.js и других языков. Крейты `pyo3` и `napi-rs` берут рутину на себя.

:: quiz
Почему вызов функции из `extern "C"` нужно оборачивать в `unsafe`?
[x] Rust не может проверить, что делает чужая функция => Верно. Ответственность на тебе.
[ ] C-функции всегда медленные => Скорость тут ни при чём.
[ ] Так требует операционная система => Это требование Rust, а не системы.

:: fill
Заполни пропуски: сделать C-строку и получить на неё указатель.
```rust
use std::ffi::CString;

let s = ___::new("hello").unwrap();
let p = s.___();
```
= CString
= as_ptr
explain: `CString::new` добавляет нулевой байт в конце, а `as_ptr()` даёт указатель для C.

:: recap
- `unsafe extern "C" { fn ...; }` — объявить C-функции. Вызов — в `unsafe`.
- `CString` / `CStr` — строки на границе с C.
- `#[unsafe(no_mangle)] pub extern "C" fn` — функция Rust для других языков.

## LESSON a11-p | Практика: unsafe | 12 | practice
:: goals
- Поработать с сырыми указателями и безопасными обёртками

:: task
Через сырой указатель `*mut i32` увеличь каждый элемент массива на 1. Используй `as_mut_ptr()` и `add(i)`.
```rust
fn main() {
    let mut a = [1, 2, 3, 4];
    let p = a.as_mut_ptr();
    for i in 0..a.len() {
        // твой код
    }
    println!("{a:?}");
}
```
```solution
fn main() {
    let mut a = [1, 2, 3, 4];
    let p = a.as_mut_ptr();
    for i in 0..a.len() {
        // SAFETY: i < a.len(), указатель внутри массива
        unsafe {
            *p.add(i) += 1;
        }
    }
    println!("{a:?}");
}
```
```expect
[2, 3, 4, 5]
```
hint: `unsafe { *p.add(i) += 1; }`.

:: task
Функция `swap_ends` меняет местами первый и последний элементы через сырые указатели. Добавь проверку на пустой срез: тогда ничего не делать.
```rust
fn swap_ends(v: &mut [i32]) {
    // твой код
}

fn main() {
    let mut a = [1, 2, 3, 4];
    swap_ends(&mut a);
    println!("{a:?}");
    let mut empty: [i32; 0] = [];
    swap_ends(&mut empty);
    println!("{empty:?}");
}
```
```solution
fn swap_ends(v: &mut [i32]) {
    if v.is_empty() {
        return;
    }
    let last = v.len() - 1;
    let p = v.as_mut_ptr();
    // SAFETY: срез не пуст, поэтому индексы 0 и last внутри него
    unsafe {
        std::ptr::swap(p, p.add(last));
    }
}

fn main() {
    let mut a = [1, 2, 3, 4];
    swap_ends(&mut a);
    println!("{a:?}");
    let mut empty: [i32; 0] = [];
    swap_ends(&mut empty);
    println!("{empty:?}");
}
```
```expect
[4, 2, 3, 1]
[]
```
hint: Сначала `if v.is_empty() { return; }`.
hint: `std::ptr::swap(p, p.add(last))` меняет местами значения по двум указателям.

:: task
Вызови C-функцию `abs` для каждого числа и выведи сумму модулей.
```rust
use std::os::raw::c_int;

unsafe extern "C" {
    fn abs(x: c_int) -> c_int;
}

fn main() {
    let nums = [-3, 5, -7];
    // твой код
}
```
```solution
use std::os::raw::c_int;

unsafe extern "C" {
    fn abs(x: c_int) -> c_int;
}

fn main() {
    let nums = [-3, 5, -7];
    let total: i32 = nums.iter().map(|&n| unsafe { abs(n) }).sum();
    println!("{total}");
}
```
```expect
15
```
hint: `nums.iter().map(|&n| unsafe { abs(n) }).sum()`.

:: recap
- `as_mut_ptr()` + `add(i)` — ходить по массиву указателем.
- Перед `unsafe` — проверка и `// SAFETY:`.
- Вызовы C — тоже в `unsafe`.
