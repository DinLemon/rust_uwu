# MODULE m13 | Времена жизни | Сколько живёт ссылка

## LESSON m13-1 | Зачем нужны времена жизни | 6
:: goals
- Что такое время жизни ссылки
- Почему компилятор иногда просит `'a`

:: text Вспомним висячие ссылки
Мы уже знаем: ссылка не может пережить значение.

Обычно компилятор сам видит, сколько что живёт. Но иногда ему **непонятно**. Тогда он просит подсказку — **метку времени жизни** (lifetime): `'a`.

!> Метка ничего не продлевает. Она только **описывает** связь: «эта ссылка живёт не дольше той».

:: code
Функция возвращает ссылку на одну из двух строк. Запусти.
```rust
fn longest(a: &str, b: &str) -> &str {
    if a.len() > b.len() { a } else { b }
}

fn main() {
    println!("{}", longest("кот", "бегемот"));
}
```
fails: yes
Ошибка `E0106`: «нужен параметр времени жизни». Компилятор не знает, от **какой** из двух строк зависит результат.

:: text Подсказываем компилятору
```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}
```
Читается так: «есть время жизни `'a`. Обе строки живут хотя бы `'a`. Результат тоже живёт `'a`».

Проще: **результат проживёт столько, сколько короче живущая из двух строк**.

:: code
```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}

fn main() {
    let first = String::from("кот");
    let result;
    {
        let second = String::from("бегемот");
        result = longest(&first, &second);
        println!("Длиннее: {result}");
    }
}
```
```out
Длиннее: бегемот
```
Попробуй перенести `println!` за закрывающую `}`. Компилятор не разрешит: `second` уже умерла, а `result` может на неё смотреть.

:: quiz
Что делает метка `'a` в `fn f<'a>(x: &'a str) -> &'a str`?
[ ] Заставляет `x` жить дольше => Метки ничего не продлевают.
[x] Говорит: результат живёт не дольше, чем `x` => Верно. Это описание связи для компилятора.
[ ] Делает ссылку изменяемой => За изменяемость отвечает `mut`.

:: deep Как компилятор думает о временах жизни
Для каждой ссылки компилятор находит **участок кода**, где она используется: от создания до последнего использования. Для каждого значения — участок, где оно живо.

Потом он проверяет одно правило: участок ссылки должен **целиком** помещаться в участок значения.

Метка `'a` — это имя для такого участка. В `longest<'a>` мы говорим: «результат используется только там, где живы обе строки». Компилятор проверяет это в каждом месте вызова.

:: recap
- Время жизни — сколько живёт ссылка.
- Метка `'a` описывает связь между ссылками, но не продлевает жизнь.
- Компилятор просит метки, когда сам не может понять связь.

## LESSON m13-2 | Когда метки не нужны | 5
:: goals
- Правила, по которым компилятор угадывает сам
- Что такое `'static`

:: text Компилятор часто догадывается сам
Правила угадывания называют **элизией** (пропуском). Главные случаи:

- Одна входная ссылка → результат живёт столько же, сколько она.
- Метод с `&self` → результат живёт столько же, сколько `self`.

Поэтому `fn first_word(s: &str) -> &str` работает без меток. Метки нужны, когда входных ссылок **несколько** и непонятно, какая главная.

:: text 'static — живёт всю программу
`'static` — особое время жизни: «до конца программы».

Текст в кавычках — `&'static str`. Он вшит прямо в программу и живёт всегда.

```rust
let s: &'static str = "я живу вечно";
```

:: quiz
Нужна ли метка времени жизни в `fn trim(s: &str) -> &str`?
[x] Нет, ссылка на входе одна, компилятор догадается => Верно. Это правило элизии.
[ ] Да, всегда, когда возвращается ссылка => Только если компилятор не может догадаться сам.

:: text Три правила угадывания
Полностью правила элизии такие:
1. Каждая входная ссылка получает **свою** метку.
2. Если входная ссылка **одна**, результат получает её метку.
3. Если среди входов есть `&self` или `&mut self`, результат получает метку `self`.

Если после этих правил у результата всё ещё нет метки, компилятор просит написать её вручную. Это и есть ошибка `E0106`.

:: recap
- При одной входной ссылке или `&self` метки обычно не нужны.
- `'static` — живёт всю программу. Строки в кавычках — `&'static str`.

## LESSON m13-3 | Ссылки в структурах | 5
:: goals
- Хранить ссылку внутри структуры
- Понимать запись `struct Name<'a>`

:: text Структура со ссылкой
Структура может не владеть данными, а смотреть на чужие. Тогда нужна метка: структура не должна пережить то, на что смотрит.

```rust
struct Quote<'a> {
    text: &'a str,
}
```

:: code
```rust
struct Highlight<'a> {
    part: &'a str,
}

impl<'a> Highlight<'a> {
    fn show(&self) {
        println!("Главное: «{}»", self.part);
    }
}

fn main() {
    let book = String::from("Rust надёжен. И быстр.");
    let first = book.split('.').next().unwrap();
    let h = Highlight { part: first };
    h.show();
}
```
```out
Главное: «Rust надёжен»
```

:: text Совет новичку
Сомневаешься? Храни в структуре `String`, а не `&str`. Структура будет владеть данными, и меток не понадобится.

Ссылки в структурах — это оптимизация. К ней можно прийти потом.

:: quiz
Что проще всего сделать, если метки в структуре запутали?
[x] Хранить `String` вместо `&str` => Верно. Владеющий тип не требует меток.
[ ] Поставить `'static` везде => Тогда в структуру можно будет класть только вечные строки. Это неудобно.
[ ] Удалить структуру => Слишком радикально. Достаточно поменять тип поля.

:: deep 'static в требованиях к типу
Запись `T: 'static` в требованиях к типу значит не «живёт вечно», а «**не содержит** временных ссылок». `String`, `i32`, `Vec<u8>` подходят: они владеют своими данными.

Такое требование есть, например, у `thread::spawn`: поток может жить сколько угодно, поэтому брать с собой временные ссылки ему нельзя. Про потоки — в модуле 17.

:: recap
- Структура со ссылкой: `struct S<'a> { x: &'a str }`.
- Структура не может пережить данные, на которые смотрит.
- Хранить `String` вместо `&str` — простой выход.

## LESSON m13-p | Практика: времена жизни | 10 | practice
:: goals

:: task
Почини ошибку `E0106`: добавь метку времени жизни.
```rust
fn shorter(a: &str, b: &str) -> &str {
    if a.len() < b.len() { a } else { b }
}

fn main() {
    println!("{}", shorter("кот", "бегемот"));
}
```
```solution
fn shorter<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() < b.len() { a } else { b }
}

fn main() {
    println!("{}", shorter("кот", "бегемот"));
}
```
```expect
кот
```
hint: Объяви метку после имени функции: `fn shorter<'a>(...)`.
hint: `fn shorter<'a>(a: &'a str, b: &'a str) -> &'a str`

:: task
Функция всегда возвращает первую строку. Тогда вторая строка может жить сколько угодно. Опиши это двумя разными метками.
```rust
fn pick_first(a: &str, b: &str) -> &str {
    println!("Второе: {b}");
    a
}

fn main() {
    let x = String::from("первое");
    let r;
    {
        let y = String::from("второе");
        r = pick_first(&x, &y);
    }
    println!("{r}");
}
```
```solution
fn pick_first<'a, 'b>(a: &'a str, b: &'b str) -> &'a str {
    println!("Второе: {b}");
    a
}

fn main() {
    let x = String::from("первое");
    let r;
    {
        let y = String::from("второе");
        r = pick_first(&x, &y);
    }
    println!("{r}");
}
```
```expect
Второе: второе
первое
```
hint: Две метки: `fn pick_first<'a, 'b>(a: &'a str, b: &'b str) -> &'a str`
hint: Результат связан только с `a`, поэтому `y` может умереть раньше, чем используется `r`.

:: task
Структура со ссылкой. Допиши метод `word_count`, который считает слова в тексте.
```rust
struct Note<'a> {
    text: &'a str,
}

impl<'a> Note<'a> {
}

fn main() {
    let s = String::from("ссылки в структурах работают");
    let n = Note { text: &s };
    println!("{}", n.word_count());
}
```
```solution
struct Note<'a> {
    text: &'a str,
}

impl<'a> Note<'a> {
    fn word_count(&self) -> usize {
        self.text.split_whitespace().count()
    }
}

fn main() {
    let s = String::from("ссылки в структурах работают");
    let n = Note { text: &s };
    println!("{}", n.word_count());
}
```
```expect
4
```
hint: Метод только читает: `fn word_count(&self) -> usize`.
hint: `self.text.split_whitespace().count()`

:: quiz
Какой функции **нужна** явная метка времени жизни?
[ ] `fn len(s: &str) -> usize` => Результат — не ссылка. Метка не нужна.
[ ] `fn first(s: &str) -> &str` => Входная ссылка одна, компилятор догадается сам.
[x] `fn pick(a: &str, b: &str) -> &str` => Верно. Две входные ссылки — непонятно, с какой связан результат.

:: recap
- E0106 — добавь метку `'a` и свяжи ею вход и результат.
- Разные метки — значит, ссылки живут независимо.
- Структура со ссылкой: `struct S<'a>` и `impl<'a> S<'a>`.
