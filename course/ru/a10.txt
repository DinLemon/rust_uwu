# MODULE a10 | Макросы глубже | Фрагменты, повторения, рекурсия и derive

## LESSON a10-1 | Фрагменты: что умеет ловить макрос | 7
:: goals
- Знать основные виды фрагментов: `expr`, `ident`, `ty`, `literal`, `tt`
- Написать макрос, который создаёт функцию

:: text Напоминание
Макрос `macro_rules!` — это «найди образец — подставь шаблон». Он работает **до** компиляции: пишет код за тебя.

```rust
macro_rules! square {
    ($x:expr) => { $x * $x };
}
```
`$x:expr` — «поймай выражение и назови его `$x`». Тип после двоеточия называют **фрагментом**.

> **Аналогия:** форма с полями. «Имя: ___ Возраст: ___». Фрагмент говорит, что можно вписать в поле: имя, число, дату.

:: text Самые нужные фрагменты
- `expr` — выражение: `2 + 3`, `foo(x)`, `"текст"`.
- `ident` — имя: `count`, `my_function`.
- `ty` — тип: `i32`, `Vec<String>`.
- `literal` — литерал: `42`, `"привет"`, `true`.
- `tt` — один «токен» или группа в скобках. Самый гибкий.
- `block` — блок `{ ... }`, `pat` — образец для `match`.

:: code
`ident` позволяет макросу **придумать имя** функции:
```rust
macro_rules! getter {
    ($name:ident, $value:expr) => {
        fn $name() -> i32 {
            $value
        }
    };
}

getter!(answer, 42);
getter!(year, 2015);

fn main() {
    println!("{} {}", answer(), year());
}
```
```out
42 2015
```
Макрос написал две функции. Обычная функция так не умеет: она не может создать другую функцию с именем из аргумента.

:: quiz
Какой фрагмент поймает имя переменной или функции?
[ ] `expr` => `expr` — выражение. Имя тоже выражение, но использовать его как имя новой функции нельзя.
[x] `ident` => Верно.
[ ] `ty` => Это тип.

:: fill
Заполни фрагменты: макрос создаёт структуру с одним полем заданного типа.
```rust
macro_rules! wrapper {
    ($name:___, $inner:___) => {
        struct $name($inner);
    };
}

wrapper!(Meters, f64);
```
= ident
= ty
explain: Имя структуры — `ident`, тип поля — `ty`.

:: task
Напиши макрос `max_of!(a, b)`, который возвращает большее из двух выражений.
```rust
macro_rules! max_of {
    // твой код
}

fn main() {
    println!("{}", max_of!(3, 7));
    println!("{}", max_of!(10 * 2, 15));
}
```
```solution
macro_rules! max_of {
    ($a:expr, $b:expr) => {
        if $a > $b { $a } else { $b }
    };
}

fn main() {
    println!("{}", max_of!(3, 7));
    println!("{}", max_of!(10 * 2, 15));
}
```
```expect
7
20
```
hint: `($a:expr, $b:expr) => { if $a > $b { $a } else { $b } };`.

:: deep Почему лучше одна переменная
В `max_of!` выражение `$a` подставляется **дважды**. Если там вызов функции с побочным эффектом (например, печать), он выполнится два раза.

Аккуратный вариант:
```rust
($a:expr, $b:expr) => {{
    let a = $a;
    let b = $b;
    if a > b { a } else { b }
}};
```
Двойные скобки `{{ }}` — макрос возвращает **блок**, в котором можно заводить переменные. И эти `a`, `b` не смешаются с переменными снаружи — об этом урок про гигиену.

:: recap
- Фрагмент — что ловит `$x:...`: `expr`, `ident`, `ty`, `literal`, `tt`.
- `ident` даёт макросам создавать функции и типы с нужными именами.
- Макрос работает до компиляции: пишет код.

## LESSON a10-2 | Повторения | 8
:: goals
- Ловить сколько угодно аргументов через `$( ... ),*`
- Разворачивать повторения в шаблоне

:: text Как vec! принимает сколько угодно
`vec![1, 2, 3]`, `vec![1]`, `vec![]` — один макрос, разное число аргументов. Секрет — **повторение**:

```rust
$( $x:expr ),*
```
- `$( ... )` — группа, которая повторяется;
- `,` — разделитель между повторами;
- `*` — «ноль или больше раз». Есть ещё `+` — «один или больше» и `?` — «ноль или один».

:: code
```rust
macro_rules! my_vec {
    ( $( $x:expr ),* ) => {{
        let mut v = Vec::new();
        $( v.push($x); )*
        v
    }};
}

fn main() {
    let a = my_vec![1, 2, 3];
    let b: Vec<i32> = my_vec![];
    println!("{a:?} {b:?}");
}
```
```out
[1, 2, 3] []
```
В шаблоне `$( v.push($x); )*` — «для каждого пойманного `$x` напиши строку `v.push(...)`».

> **Аналогия:** почтальон с пачкой писем. Правило одно: «опустить в ящик». Сколько писем — столько раз и повторит.

:: code
Можно ловить **пары**:
```rust
use std::collections::BTreeMap;

macro_rules! map {
    ( $( $k:expr => $v:expr ),* $(,)? ) => {{
        let mut m = BTreeMap::new();
        $( m.insert($k, $v); )*
        m
    }};
}

fn main() {
    let ages = map! {
        "Аня" => 30,
        "Боря" => 25,
    };
    println!("{ages:?}");
}
```
```out
{"Аня": 30, "Боря": 25}
```
`$(,)?` в конце — «можно поставить лишнюю запятую». Удобно, когда пишешь в столбик.

:: quiz
Что значит `+` в `$( $x:expr ),+`?
[ ] Аргументы складываются => Это не сложение, а количество повторов.
[x] Один или больше аргументов => Верно. Пустой вызов не подойдёт.
[ ] Ноль или больше => Это `*`.

:: task
Напиши макрос `sum!`, который складывает любое количество выражений (хотя бы одно).
```rust
macro_rules! sum {
    // твой код
}

fn main() {
    println!("{}", sum!(1));
    println!("{}", sum!(1, 2, 3, 4));
}
```
```solution
macro_rules! sum {
    ( $( $x:expr ),+ ) => {
        0 $( + $x )+
    };
}

fn main() {
    println!("{}", sum!(1));
    println!("{}", sum!(1, 2, 3, 4));
}
```
```expect
1
10
```
hint: Образец: `( $( $x:expr ),+ )`.
hint: Шаблон: `0 $( + $x )+` — получится `0 + 1 + 2 + 3 + 4`.

:: recap
- `$( ... ),*` — повторение через запятую, ноль или больше раз.
- `+` — один или больше, `?` — ноль или один.
- В шаблоне `$( ... )*` повторяет кусок кода для каждого пойманного.

## LESSON a10-3 | Несколько правил, рекурсия, гигиена | 8
:: goals
- Писать макрос с несколькими вариантами
- Понять, как макрос вызывает сам себя
- Узнать, почему переменные макроса не мешают твоим

:: text Несколько правил
У макроса может быть несколько веток, как у `match`. Rust пробует их **сверху вниз** и берёт первую подходящую.

```rust
macro_rules! greet {
    () => { println!("Привет!") };
    ($name:expr) => { println!("Привет, {}!", $name) };
}
```
`greet!()` и `greet!("Аня")` — оба работают.

:: text Рекурсия
Макрос может вызвать **сам себя** с меньшим числом аргументов. Так делают сложную обработку: «откуси первый — остальное отдай себе же».

:: code
```rust
macro_rules! count {
    () => { 0usize };
    ($head:tt $($tail:tt)*) => { 1usize + count!($($tail)*) };
}

fn main() {
    println!("{}", count!());
    println!("{}", count!(a b c));
    println!("{}", count!(x y z w q));
}
```
```out
0
3
5
```
`count!(a b c)` → `1 + count!(b c)` → `1 + 1 + count!(c)` → `1 + 1 + 1 + count!()` → `1 + 1 + 1 + 0`.

> **Аналогия:** матрёшка. Открыл одну, внутри такая же поменьше. И так до самой маленькой.

:: text Гигиена
Переменные, которые макрос заводит **внутри себя**, не видны снаружи и не путаются с твоими. Даже если имена совпадают.

```rust
macro_rules! make_x {
    () => { let x = 100; };
}

let x = 1;
make_x!();
println!("{x}"); // 1 — у макроса был свой x
```
Это называют **гигиеной**. Она защищает от случайных конфликтов имён. Хочешь, чтобы макрос создал переменную для тебя? Передай её имя через `ident`.

:: quiz
`let total = 5;` а затем макрос внутри себя пишет `let total = 0;`. Что будет с твоим `total` после вызова?
[x] Останется 5 => Верно. Гигиена отделяет переменные макроса.
[ ] Станет 0 => Так было бы в C, но не в Rust.
[ ] Ошибка компиляции => Никакого конфликта нет.

:: task
Напиши макрос `say!` с двумя правилами: без аргументов печатает `...`, с одним — печатает его в кавычках-ёлочках: `«текст»`.
```rust
macro_rules! say {
    // твой код
}

fn main() {
    say!();
    say!("привет");
}
```
```solution
macro_rules! say {
    () => {
        println!("...")
    };
    ($msg:expr) => {
        println!("«{}»", $msg)
    };
}

fn main() {
    say!();
    say!("привет");
}
```
```expect
...
«привет»
```
hint: Два правила через `;`: `() => { ... };` и `($msg:expr) => { ... };`.

:: deep Как отлаживать макросы
Когда макрос ведёт себя странно, полезно увидеть, во что он **развернулся**.

- Инструмент `cargo expand` (ставится отдельно: `cargo install cargo-expand`) показывает код после раскрытия всех макросов.
- В Rust Playground есть пункт меню **Tools → Expand macros**.

Ещё один приём — временно заменить тело на `stringify!(...)`: макрос напечатает, что он поймал, как строку.

:: recap
- Несколько правил — пробуются сверху вниз.
- Рекурсия: обработай первый, остальное отдай себе же.
- Гигиена: переменные макроса не смешиваются с твоими.

## LESSON a10-4 | Процедурные макросы и derive | 7
:: goals
- Понять, чем процедурный макрос отличается от `macro_rules!`
- Использовать `#[derive(Serialize)]` из serde

:: text Два вида макросов
- `macro_rules!` — **по образцу**. Пишется прямо в коде, быстро и просто.
- **Процедурные** — маленькие программы на Rust, которые получают код и возвращают новый код. Живут в отдельном крейте. Умеют гораздо больше.

Процедурные бывают трёх видов:
- `#[derive(Имя)]` над структурой — дописать реализацию трейта;
- атрибуты, например `#[tokio::main]`;
- похожие на функцию: `sql!(...)`.

Ты уже пользовался ими: `#[derive(Debug)]`, `#[tokio::main]`, `#[derive(Error)]`.

> **Аналогия:** `macro_rules!` — трафарет. Процедурный макрос — маленький робот, который читает твой чертёж и сам дорисовывает детали.

:: code
serde — самый известный пример. Одна строчка `derive` — и структура умеет превращаться в JSON и обратно:
```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize)]
struct Cat {
    name: String,
    age: u8,
    toys: Vec<String>,
}

fn main() {
    let c = Cat { name: String::from("Барсик"), age: 3, toys: vec![String::from("мышь")] };
    let json = serde_json::to_string(&c).unwrap();
    println!("{json}");

    let back: Cat = serde_json::from_str(r#"{"name":"Мурка","age":5,"toys":[]}"#).unwrap();
    println!("{back:?}");
}
```
crates: yes
```out
{"name":"Барсик","age":3,"toys":["мышь"]}
Cat { name: "Мурка", age: 5, toys: [] }
```
Никакого кода для JSON мы не писали. Его сгенерировал `derive`.

:: text Атрибуты полей
Процедурные макросы читают и дополнительные пометки. У serde их много:

```rust
#[derive(Serialize)]
struct User {
    #[serde(rename = "userName")]
    name: String,
    #[serde(skip)]
    password: String,
}
```
- `rename` — в JSON поле будет называться по-другому;
- `skip` — не выводить поле вообще.

:: quiz
Где живёт процедурный макрос, например `derive(Serialize)`?
[ ] Прямо в твоём файле, как `macro_rules!` => Процедурные макросы пишут в отдельном крейте.
[x] В отдельном крейте с типом `proc-macro` => Верно. serde подключает его за тебя.
[ ] В компиляторе Rust => Нет, это обычный крейт.

:: deep Как написать свой derive
Свой процедурный макрос — это крейт с `proc-macro = true` в `Cargo.toml`. Внутри функция с атрибутом:

```rust
#[proc_macro_derive(Hello)]
pub fn hello(input: TokenStream) -> TokenStream { ... }
```
Она получает код структуры как поток токенов и возвращает новый код. Обычно помогают два крейта:
- `syn` — разбирает токены в удобное дерево («вот структура, вот её поля»);
- `quote` — собирает новый код из шаблона: `quote! { impl Hello for #name { ... } }`.

Это уже продвинутая тема. Хороший старт — «The Little Book of Rust Macros» и раздел о макросах в официальной книге.

:: recap
- `macro_rules!` — по образцу; процедурные — программы, которые пишут код.
- `#[derive(...)]`, атрибуты и функции-макросы — три вида процедурных.
- serde: `derive(Serialize, Deserialize)` + `serde_json`.

## LESSON a10-p | Практика: макросы | 14 | practice
:: goals
- Написать несколько полезных макросов с повторениями

:: task
Макрос `set!` создаёт `BTreeSet` из перечисленных значений (можно с лишней запятой в конце).
```rust
use std::collections::BTreeSet;

macro_rules! set {
    // твой код
}

fn main() {
    let s = set![3, 1, 2, 3,];
    println!("{s:?}");
}
```
```solution
use std::collections::BTreeSet;

macro_rules! set {
    ( $( $x:expr ),* $(,)? ) => {{
        let mut s = BTreeSet::new();
        $( s.insert($x); )*
        s
    }};
}

fn main() {
    let s = set![3, 1, 2, 3,];
    println!("{s:?}");
}
```
```expect
{1, 2, 3}
```
hint: Образец как у `my_vec!`, плюс `$(,)?` для лишней запятой.
hint: Внутри: `let mut s = BTreeSet::new(); $( s.insert($x); )* s`.

:: task
Макрос `make_struct!` создаёт структуру с `#[derive(Debug)]` и заданными полями: `make_struct!(Point { x: i32, y: i32 })`.
```rust
macro_rules! make_struct {
    // твой код
}

make_struct!(Point { x: i32, y: i32 });

fn main() {
    let p = Point { x: 1, y: 2 };
    println!("{p:?}");
}
```
```solution
macro_rules! make_struct {
    ($name:ident { $( $field:ident : $ty:ty ),* $(,)? }) => {
        #[derive(Debug)]
        struct $name {
            $( $field: $ty ),*
        }
    };
}

make_struct!(Point { x: i32, y: i32 });

fn main() {
    let p = Point { x: 1, y: 2 };
    println!("{p:?}");
}
```
```expect
Point { x: 1, y: 2 }
```
hint: Имя структуры — `$name:ident`, поля — повторение `$( $field:ident : $ty:ty ),*`.
hint: В шаблоне: `struct $name { $( $field: $ty ),* }`.

:: task
Макрос `check!` принимает несколько условий и печатает каждое, которое оказалось ложным, в виде `не выполнено: <условие>`. Используй `stringify!`.
```rust
macro_rules! check {
    // твой код
}

fn main() {
    let age = 15;
    let name = "Ада";
    check!(age >= 18, name.len() > 2, 1 + 1 == 2);
}
```
```solution
macro_rules! check {
    ( $( $cond:expr ),* ) => {
        $(
            if !$cond {
                println!("не выполнено: {}", stringify!($cond));
            }
        )*
    };
}

fn main() {
    let age = 15;
    let name = "Ада";
    check!(age >= 18, name.len() > 2, 1 + 1 == 2);
}
```
```expect
не выполнено: age >= 18
```
hint: `stringify!($cond)` превращает код условия в строку.
hint: Повтори для каждого: `$( if !$cond { println!(...); } )*`.

:: recap
- `$(,)?` — разрешить лишнюю запятую.
- `ident` + `ty` в повторении — генерировать поля структур.
- `stringify!` — превратить код в текст для сообщений.
