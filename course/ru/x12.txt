## LESSON x12-1 | Тесты-таблицы и порядок в тестах | 8
:: goals
- Писать много случаев одним тестом
- Знать, где живут юнит-, интеграционные и doc-тесты

:: text Таблица случаев
Когда случаев много, не пиши десять одинаковых `#[test]`. Сделай **таблицу**: вход и ожидаемый выход, и один цикл.

```rust
#[test]
fn roman_table() {
    let cases = [(1, "I"), (4, "IV"), (9, "IX"), (14, "XIV"), (1994, "MCMXCIV")];
    for (n, want) in cases {
        assert_eq!(roman(n), want, "для числа {n}");
    }
}
```
Третий аргумент `assert_eq!` — сообщение. Без него при провале непонятно, **какой** случай сломался.

> **Аналогия:** контрольная с ответами в конце учебника. Одна таблица — и проверяешь все задачи подряд.

:: text Где живут тесты
- **Юнит-тесты** — `mod tests` с `#[cfg(test)]` в том же файле. Видят приватные функции.
- **Интеграционные** — файлы в папке `tests/` рядом с `src/`. Видят только публичный API, как настоящий пользователь.
- **Doc-тесты** — примеры в `///`-комментариях. `cargo test` их компилирует и запускает: документация не врёт.

```rust
/// Удваивает число.
///
/// ```
/// assert_eq!(mylib::double(4), 8);
/// ```
pub fn double(x: i32) -> i32 { x * 2 }
```
Полезные мелочи:
- `#[should_panic(expected = "текст")]` — тест ждёт панику;
- тест может вернуть `Result<(), E>` и использовать `?`;
- `#[ignore]` — медленный тест, запускается через `cargo test -- --ignored`.

pub fn roman(mut n: u32) -> String {
    const TABLE: [(u32, &str); 13] = [
        (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"),
        (100, "C"), (90, "XC"), (50, "L"), (40, "XL"),
        (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I"),
    ];
    let mut out = String::new();
    for (value, sym) in TABLE {
        while n >= value {
            out.push_str(sym);
            n -= value;
        }
    }
    out
}

        }
    }
}
```

:: recap
- Тест-таблица: массив случаев и один цикл с понятным сообщением.
- Юнит — рядом с кодом, интеграционные — в `tests/`, doc-тесты — в `///`.
- `should_panic`, `Result` из теста, `#[ignore]` — для особых случаев.

## LESSON x12-2 | Тесты свойств | 10
:: goals
- Понять идею: проверять правило, а не конкретные примеры
- Сделать свой маленький генератор случайных тестов

:: text Свойство вместо примера
Обычный тест: «для `[3, 1, 2]` ответ `[1, 2, 3]`». Ты сам придумал пример — и сам мог что-то упустить.

**Тест свойства** говорит: «для **любого** списка результат сортировки упорядочен и содержит те же элементы». А примеры генерирует машина — сотни случайных.

Хорошие свойства:
- **туда и обратно**: `decode(encode(x)) == x`;
- **инвариант**: результат всегда отсортирован, длина не изменилась;
- **сравнение с простой версией**: быстрая функция отвечает так же, как медленная и очевидная.

> **Аналогия:** проверять замок не одним ключом, а связкой случайных. Если хоть один чужой открыл — замок плохой.

:: code
Свой мини-тестер: генератор случайных списков и проверка свойств. Генератор с фиксированным зерном — чтобы провал повторялся при каждом запуске.
```rust
struct Rng(u64);

impl Rng {
    fn next(&mut self) -> u64 {
        // xorshift: простой и быстрый генератор
        self.0 ^= self.0 << 13;
        self.0 ^= self.0 >> 7;
        self.0 ^= self.0 << 17;
        self.0
    }
    fn range(&mut self, n: u64) -> u64 {
        self.next() % n
    }
    fn vec(&mut self) -> Vec<i32> {
        let len = self.range(8) as usize;
        (0..len).map(|_| self.range(10) as i32).collect()
    }
}

fn check(name: &str, cases: u32, prop: impl Fn(&[i32]) -> bool) {
    let mut rng = Rng(42);
    for i in 0..cases {
        let v = rng.vec();
        if !prop(&v) {
            println!("{name}: ПРОВАЛ на попытке {i}: {v:?}");
            return;
        }
    }
    println!("{name}: ок, {cases} попыток");
}

// Убирает повторы подряд. В ней есть ошибка.
fn dedup(v: &[i32]) -> Vec<i32> {
    let mut out = Vec::new();
    for w in v.windows(2) {
        if w[0] != w[1] {
            out.push(w[0]);
        }
    }
    out
}

fn main() {
    check("reverse дважды", 100, |v| {
        let mut r = v.to_vec();
        r.reverse();
        r.reverse();
        r == v
    });
    check("dedup: нет соседей-двойников", 100, |v| {
        dedup(v).windows(2).all(|w| w[0] != w[1])
    });
    check("dedup: все значения на месте", 100, |v| {
        let d = dedup(v);
        v.iter().all(|x| d.contains(x))
    });
}
```
```out
reverse дважды: ок, 100 попыток
dedup: нет соседей-двойников: ок, 100 попыток
dedup: все значения на месте: ПРОВАЛ на попытке 0: [1, 4]
```
Первое свойство `dedup` прошло, второе поймало ошибку: последний элемент теряется. Одно свойство — мало, нужен набор.

:: quiz
Какое свойство хорошо подходит для пары `encode`/`decode`?
[x] `decode(encode(x)) == x` для любого `x` => Верно. «Туда и обратно».
[ ] `encode(x)` всегда длиннее `x` => Не всегда правда, и ничего не говорит о правильности.
[ ] `encode("abc")` равно конкретной строке => Это обычный пример, не свойство.

:: fill
Заполни пропуски: свойство «сортировка не меняет длину».
```rust
check("длина", 100, |v| {
    let mut s = v.___();
    s.sort();
    s.___() == v.len()
});
```
= to_vec
= len
explain: Копируем срез в `Vec`, сортируем копию и сравниваем длины.

:: recap
- Свойство — правило для любых входных данных.
- Генератор с фиксированным зерном делает провалы повторяемыми.
- Ищи свойства: туда-обратно, инварианты, сравнение с простой версией.

## LESSON x12-3 | Сжатие: от большого провала к маленькому | 9
:: goals
- Понять, зачем сжимать найденный пример
- Сделать простое сжатие для списков

:: text Сжатие
Случайный провал часто огромный: список из 80 чисел. Читать такое тяжело. **Сжатие** (shrinking) пробует упростить пример, пока он всё ещё ломает свойство:

- убрать один элемент;
- заменить число на `0` или на половину.

Если упрощённый пример тоже падает — берём его и пробуем ещё. Не падает больше ничего — готово: это **минимальный** пример, который видно глазами.

proptest и quickcheck делают это сами. Сейчас — своё, чтобы понять механику.

> **Аналогия:** врач ищет аллерген. Убирает из меню по одному продукту, пока не останется тот единственный, от которого сыпь.

:: code
```rust
fn dedup(v: &[i32]) -> Vec<i32> {
    let mut out = Vec::new();
    for w in v.windows(2) {
        if w[0] != w[1] {
            out.push(w[0]);
        }
    }
    out
}

fn keeps_values(v: &[i32]) -> bool {
    let d = dedup(v);
    v.iter().all(|x| d.contains(x))
}

fn shrink(v: &[i32], prop: impl Fn(&[i32]) -> bool) -> Vec<i32> {
    let mut cur = v.to_vec();
    'outer: loop {
        // 1) пробуем убрать один элемент
        for i in 0..cur.len() {
            let mut c = cur.clone();
            c.remove(i);
            if !prop(&c) {
                cur = c;
                continue 'outer;
            }
        }
        // 2) пробуем заменить число нулём
        for i in 0..cur.len() {
            if cur[i] != 0 {
                let mut c = cur.clone();
                c[i] = 0;
                if !prop(&c) {
                    cur = c;
                    continue 'outer;
                }
            }
        }
        return cur;
    }
}

fn main() {
    let big = [7, 3, 3, 9, 2, 8, 8, 5];
    println!("падает: {}", !keeps_values(&big));
    println!("сжато до: {:?}", shrink(&big, keeps_values));
}
```
```out
падает: true
сжато до: [0]
```
Минимальный пример: список из одного числа. `windows(2)` для него пуст — значит, цикл не добавит ничего. Ошибка видна сразу.

:: quiz
Когда сжатие останавливается?
[ ] После 100 попыток => Число попыток не главное.
[x] Когда ни одно упрощение больше не ломает свойство => Верно.
[ ] Когда список стал пустым => Пустой список может и не ломать свойство.

:: recap
- Сжатие упрощает провал, пока он остаётся провалом.
- Шаги: убрать элемент, уменьшить число.
- Маленький пример объясняет ошибку лучше любого отладчика.

## LESSON x12-4 | proptest и фаззинг | 9
:: goals
- Узнать, как выглядят настоящие инструменты: proptest и cargo-fuzz
- Понять, чем фаззинг отличается от тестов свойств

:: text proptest
**proptest** делает всё из прошлых уроков сам: генерирует, проверяет, сжимает, запоминает провалы в файл.

```rust
use proptest::prelude::*;

proptest! {
    #[test]
    fn sort_keeps_len(mut v in prop::collection::vec(any::<i32>(), 0..100)) {
        let len = v.len();
        v.sort();
        prop_assert_eq!(v.len(), len);
    }

    #[test]
    fn roundtrip(s in "[a-z]{0,20}") {
        prop_assert_eq!(decode(&encode(&s)), s);
    }
}
```
- `any::<i32>()` — любое число;
- `vec(..., 0..100)` — список длиной до 100;
- `"[a-z]{0,20}"` — строки по регулярному выражению.

Найденный провал сохраняется в `proptest-regressions/` и проверяется первым при каждом запуске.

:: text Фаззинг
**Фаззер** (cargo-fuzz на основе libFuzzer) подаёт на вход функции случайные **байты** и смотрит на покрытие кода: какие ветки выполнились. Байты, которые открыли новую ветку, он мутирует дальше.

Так он находит паники, переполнения и зависания в парсерах, которые человек не придумал бы.

```rust
// fuzz/fuzz_targets/parse.rs
#![no_main]
use libfuzzer_sys::fuzz_target;

fuzz_target!(|data: &[u8]| {
    if let Ok(s) = std::str::from_utf8(data) {
        let _ = mylib::parse(s); // не должно паниковать
    }
});
```
Разница:
- **proptest** — проверяет твои свойства на структурированных данных, работает в `cargo test`;
- **фаззер** — ищет падения на любых байтах часами, нужен nightly.

> **Аналогия:** proptest — экзаменатор с билетами по теме. Фаззер — ребёнок, который жмёт все кнопки подряд и находит ту, от которой всё ломается.

:: quiz
Что фаззер считает «интересным» входом?
[ ] Самый длинный => Длина не главное.
[x] Тот, что выполнил ещё не пройденные ветки кода => Верно. Это фаззинг с обратной связью по покрытию.
[ ] Тот, что содержит только буквы => Фаззер работает с любыми байтами.

:: homework Свойства и фаззер для своего парсера
Возьми парсер из прошлых модулей (например, `parse_query` из x11 или разбор цвета из x00) или напиши новый.

1. Добавь proptest:
```sh

```
2. Напиши минимум три свойства: «не паникует на любой строке», «туда и обратно» (если есть функция обратного преобразования), «результат удовлетворяет инварианту».
3. Найди хотя бы один провал (можно специально внести ошибку) и посмотри, до чего proptest его сжал.
4. Фаззинг (нужен nightly и Linux или macOS):
```sh

```
5. Если фаззер нашёл падение — файл с входом лежит в `fuzz/artifacts/`. Превратите его в обычный `#[test]` и почини.
[ ] Три свойства proptest проходят в `cargo test`
[ ] Видел, как proptest сжал провал до маленького примера
[ ] Фаззер отработал минуту (или ты нашёл и починил падение)
[ ] Найденные провалы превращены в обычные тесты

:: recap
- proptest: генерация, проверка, сжатие и память о провалах.
- Фаззер подаёт байты и идёт за покрытием кода.
- Найденный провал — всегда в обычный тест, чтобы не вернулся.

## LESSON x12-5 | Фейки вместо внешнего мира | 8
:: goals
- Тестировать код, который зависит от времени, сети или диска
- Подменять зависимость через трейт

:: text Шов
Код, который сам зовёт `SystemTime::now()` или ходит в сеть, тестировать тяжело: время идёт, сеть падает.

Решение — **шов**: зависимость передаётся через трейт.
- в программе — настоящая реализация (часы, HTTP-клиент);
- в тесте — **фейк**: простая структура, которой ты управляешь.

Моки-фреймворки (mockall) есть, но часто хватает ручного фейка на 10 строк.

> **Аналогия:** тренажёр для пилотов. Тот же штурвал, но погоду и отказы включает инструктор.

:: code
```rust
use std::cell::Cell;

trait Clock {
    fn now(&self) -> u64; // секунды
}

struct Session<C: Clock> {
    clock: C,
    started: u64,
    ttl: u64,
}

impl<C: Clock> Session<C> {
    fn new(clock: C, ttl: u64) -> Self {
        let started = clock.now();
        Session { clock, started, ttl }
    }
    fn expired(&self) -> bool {
        self.clock.now() - self.started >= self.ttl
    }
}

// Фейк: время двигаем руками
struct FakeClock(Cell<u64>);

impl Clock for &FakeClock {
    fn now(&self) -> u64 {
        self.0.get()
    }
}

fn main() {
    let clock = FakeClock(Cell::new(1000));
    let s = Session::new(&clock, 60);
    println!("сразу: {}", s.expired());
    clock.0.set(1059);
    println!("через 59 с: {}", s.expired());
    clock.0.set(1060);
    println!("через 60 с: {}", s.expired());
}
```
```out
сразу: false
через 59 с: false
через 60 с: true
```
Тест мгновенный и точный: никакого `sleep(60)`. Граница «ровно 60 секунд» проверена.

:: quiz
Зачем `Session` получает часы через трейт `Clock`?
[ ] Так быстрее работает => Скорость тут ни при чём.
[x] Чтобы в тесте подставить фейковые часы и управлять временем => Верно.
[ ] Без трейта нельзя хранить число => Можно; дело в подмене.

:: recap
- Внешний мир (время, сеть, диск) — за трейтом.
- В тесте — фейк, которым ты управляешь.
- Тесты без `sleep` и сети: быстрые и стабильные.

## LESSON x12-6 | Бенчмарки без самообмана | 7
:: goals
- Знать, почему наивный замер врёт
- Узнать criterion и `black_box`

:: text Почему замер врёт
`Instant::now()` до и после — самый простой замер. Но:
- в **debug**-сборке код в 10–50 раз медленнее. Мерить — только с `--release`;
- оптимизатор может **выкинуть** вычисление, результат которого не используется. Ты меряешь пустоту;
- один замер — шум: кэш, другие программы, частота процессора.

`std::hint::black_box(x)` говорит оптимизатору: «считай, что `x` кто-то использует». Вычисление не выкинут.

:: code
```rust
use std::hint::black_box;
use std::time::Instant;

fn sum_squares(n: u64) -> u64 {
    (1..=n).map(|x| x * x).sum()
}

fn main() {
    let start = Instant::now();
    let mut total = 0;
    for _ in 0..1000 {
        total += sum_squares(black_box(1000));
    }
    let elapsed = start.elapsed();
    black_box(elapsed);
    println!("сумма: {total}");
}
```
```out
сумма: 333833500000
```
Время мы не печатаем: оно разное на каждом компьютере. Важна техника: много повторов, `black_box` на входе.

:: text criterion
**criterion** делает замеры честно: прогревает, повторяет сотни раз, считает статистику и сравнивает с прошлым запуском («стало медленнее на 12%»).

```rust
// benches/sum.rs
use criterion::{criterion_group, criterion_main, Criterion};
use std::hint::black_box;

fn bench(c: &mut Criterion) {
    c.bench_function("sum_squares 1000", |b| b.iter(|| mylib::sum_squares(black_box(1000))));
}

criterion_group!(benches, bench);
criterion_main!(benches);
```
В `Cargo.toml`:
```toml
[[bench]]
name = "sum"
harness = false
```

pub fn parse_duration(s: &str) -> Option<u32> {
    if s.is_empty() {
        return None;
    }
    let mut total = 0;
    let mut num = String::new();
    for c in s.chars() {
        if c.is_ascii_digit() {
            num.push(c);
            continue;
        }
        let mult = match c {
            'h' => 3600,
            'm' => 60,
            's' => 1,
            _ => return None,
        };
        let n: u32 = num.parse().ok()?;
        total += n * mult;
        num.clear();
    }
    if !num.is_empty() {
        return None;
    }
    Some(total)
}

```solution
fn shrink_u32(start: u32, fails: impl Fn(u32) -> bool) -> u32 {
    let mut n = start;
    loop {
        let next = [0, n / 2, n.saturating_sub(1)]
            .into_iter()
            .find(|&c| c < n && fails(c));
        match next {
            Some(c) => n = c,
            None => return n,
        }
    }
}

fn main() {
    println!("{}", shrink_u32(1000, |n| n * n > 2000));
    println!("{}", shrink_u32(98765, |n| n.to_string().contains('7')));
    println!("{}", shrink_u32(5, |n| n > 100));
}
```

hint: Третий случай: `5` и так не ломает проверку, но мы просто возвращаем стартовое число, раз сжать нечего.

use std::collections::BTreeSet;

struct Rng(u64);

impl Rng {
    fn next(&mut self) -> u64 {
        self.0 ^= self.0 << 13;
        self.0 ^= self.0 >> 7;
        self.0 ^= self.0 << 17;
        self.0
    }
    fn vec(&mut self) -> Vec<i32> {
        let len = (self.next() % 6) as usize;
        (0..len).map(|_| (self.next() % 5) as i32).collect()
    }
}

// Ошибка: множество выкидывает повторы
fn bad_sort(v: &[i32]) -> Vec<i32> {
    v.iter().copied().collect::<BTreeSet<_>>().into_iter().collect()
}

fn sort_ok(input: &[i32], output: &[i32]) -> bool {
    let sorted = output.windows(2).all(|w| w[0] <= w[1]);
    let mut a = input.to_vec();
    let mut b = output.to_vec();
    a.sort();
    b.sort();
    sorted && a == b
}

fn main() {
    let mut rng = Rng(7);
    for i in 0..100 {
        let v = rng.vec();
        if !sort_ok(&v, &bad_sort(&v)) {
            println!("провал на попытке {i}: {v:?} -> {:?}", bad_sort(&v));
            return;
        }
    }
    println!("ок");
}
```

провал на попытке 0: [2, 3, 2] -> [2, 3]
```
hint: Упорядоченность: `output.windows(2).all(|w| w[0] <= w[1])`.
hint: «Те же числа столько же раз»: отсортируй копии входа и выхода и сравни их целиком.
