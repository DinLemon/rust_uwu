# MODULE m05 | Владение | Главная идея Rust. Медленно и по шагам

## LESSON m05-1 | Где живут данные: стек и куча | 6
:: goals
- Что такое стек и куча
- Почему это вообще важно

:: text Зачем этот модуль
Это **самая важная** тема Rust. Именно она делает Rust быстрым и надёжным.

Она же кажется самой странной. Поэтому здесь уроки особенно маленькие. Не торопись. Если что-то не щёлкнуло с первого раза — это нормально.

:: text Память программы
Пока программа работает, данные лежат в **памяти**. У памяти есть два места:

- **стек** (stack) — быстрая полка для вещей известного размера;
- **куча** (heap) — большой склад для вещей, размер которых может меняться.

:: text Стек — стопка тарелок
Числа, `bool`, `char` всегда одного размера. Они лежат на **стеке**.

> Стек — как стопка тарелок. Кладут сверху, берут сверху. Очень быстро и просто.

Когда функция заканчивается, её тарелки снимаются со стопки сами.

:: text Куча — склад
Текст, который может расти, хранится в **куче**. Например, тип `String`.

> Куча — как склад. Кладовщик находит свободное место, кладёт вещь и выдаёт тебе **номерок**. Номерок лежит на стеке, а сама вещь — на складе.

Главный вопрос: **кто и когда освободит место на складе?** Вот на него и отвечает владение.

:: quiz
Где хранится текст `String`, который может расти?
[ ] Только на стеке => На стеке лежит лишь «номерок»: адрес, длина, вместимость.
[x] В куче, а на стеке — указатель на него => Верно. Как вещь на складе и номерок в кармане.
[ ] Нигде, он вычисляется на лету => Данные всегда где-то лежат в памяти.

:: text Как другие языки убирают склад
- В C программист убирает **вручную**. Забыл — память течёт. Убрал дважды — программа падает.
- В Python, Java, C# работает **сборщик мусора**. Он сам ходит и убирает. Удобно, но тратит время.
- В Rust уборка расписана **заранее**, ещё при компиляции. Это и есть **владение**.

:: recap
- Стек — быстрая стопка для данных известного размера.
- Куча — склад для данных, которые могут расти.
- Владение решает, кто и когда освобождает место в куче.

## LESSON m05-2 | Три правила владения | 6
:: goals
- Выучить три правила владения
- Понять, когда значение удаляется

:: text Три правила
Вся система владения — это всего три правила:

1. У каждого значения есть **владелец** — переменная.
2. Владелец в каждый момент **только один**.
3. Когда владелец выходит из области видимости, значение **удаляется**.

> Как с книгой. У книги один хозяин. Хозяин уехал навсегда — книгу сдали в макулатуру.

:: code
Правило 3 в деле. Создадим `String` внутри блока.
```rust
fn main() {
    {
        let s = String::from("привет");
        println!("{s}");
    } // здесь s выходит из области видимости — память освобождается
    println!("блок закончился");
}
```
```out
привет
блок закончился
```
`String::from("...")` создаёт строку в куче. На `}` Rust сам вызывает уборку. Писать ничего не нужно.

:: quiz
Когда освобождается память строки `s` в примере выше?
[ ] В конце `main` => Раньше: `s` живёт только внутри своего блока.
[x] На закрывающей `}` блока, где создана `s` => Верно. Владелец ушёл — значение удалено.
[ ] Никогда, пока программа работает => В Rust память освобождается сразу, как только владелец исчез.

:: fill
Вспомни правила. Заполни пропуски одним словом.
```rust
// 1. У каждого значения есть ___.
// 2. Владелец в каждый момент только ___.
// 3. Владелец ушёл — значение ___.
```
= владелец
= один | одна | 1
= удаляется | удалится | удалено
explain: Это всё, на чём держится владение.

:: recap
- У значения один владелец.
- Владелец вышел из блока — значение удалено.
- Уборку пишет компилятор, а не ты.

## LESSON m05-3 | Перемещение (move) | 7
:: goals
- Что происходит при `let b = a;` со строкой
- Почему старая переменная перестаёт работать

:: text Отдал книгу — её у тебя нет
Что будет, если написать `let b = a;`, где `a` — `String`?

Правило 2: владелец один. Значит, книга **переходит** к `b`. А у `a` её больше нет.

Это называется **перемещение** (move).

:: code
Запусти. Что скажет компилятор?
```rust
fn main() {
    let a = String::from("книга");
    let b = a;
    println!("{a}");
}
```
fails: yes
Ошибка `E0382: borrow of moved value: a` — «использование перемещённого значения». Значение уехало в `b`. Переменная `a` теперь пустая.

:: text Почему так сделано
Если бы `a` и `b` обе владели строкой, на `}` её удалили бы **дважды**. В C это классическая авария.

Rust просто запрещает так делать. Ошибка ловится на компиляции, а не у пользователя.

:: quiz
Что напечатает программа?
```rust
fn main() {
    let a = String::from("кот");
    let b = a;
    println!("{b}");
}
```
[x] кот => Верно. Теперь владелец — `b`, и печатать его можно.
[ ] Ошибка компиляции => Ошибка была бы при обращении к `a`. А `b` — законный владелец.
[ ] Пустую строку => Данные никуда не делись, просто сменился хозяин.

:: text Функция тоже забирает
Передать значение в функцию — это тоже перемещение. Функция становится владельцем.

```rust
fn eat(food: String) {
    println!("Съел {food}");
} // тут food удаляется

fn main() {
    let apple = String::from("яблоко");
    eat(apple);
    // apple больше нельзя использовать
}
```

:: quiz
После `eat(apple);` можно ли напечатать `apple`?
[ ] Да, функция только посмотрела => Без `&` функция не смотрит, а забирает.
[x] Нет, значение переехало в функцию => Верно. И удалилось в конце `eat`.

:: recap
- `let b = a;` со `String` перемещает значение.
- После перемещения старой переменной пользоваться нельзя: ошибка E0382.
- Передача в функцию — тоже перемещение.

## LESSON m05-4 | clone и Copy | 6
:: goals
- Как сделать копию через `.clone()`
- Почему числа копируются сами

:: text clone — ксерокопия
Нужно, чтобы данные были и у `a`, и у `b`? Сделай **копию**: `.clone()`.

```rust
let a = String::from("текст");
let b = a.clone();
println!("{a} и {b}"); // работает
```
> Это ксерокопия книги. Теперь у каждого своя. Но копировать большую книгу — долго, поэтому делай это осознанно.

:: code
А с числами всё работает и без `clone`. Почему?
```rust
fn main() {
    let x = 5;
    let y = x;
    println!("x = {x}, y = {y}");
}
```
```out
x = 5, y = 5
```

:: text Тип Copy
Маленькие простые значения лежат на стеке. Копировать их дёшево. Поэтому Rust копирует их **сам**.

Такие типы называются **Copy**: все числа, `bool`, `char` и кортежи из них.

> Число — как записка с цифрой. Её легко переписать на другую бумажку. А `String` — целая книга.

:: quiz
Какой из этих типов НЕ копируется сам при `let b = a;`?
[ ] `i32` => Целые числа — Copy.
[ ] `bool` => `bool` — Copy.
[x] `String` => Верно. `String` лежит в куче, он перемещается.
[ ] `char` => `char` — Copy.

:: task
Почини программу: добавь копию, чтобы обе строки напечатались.
```rust
fn main() {
    let original = String::from("Rust");
    let copy = original;
    println!("{original} и {copy}");
}
```
```solution
fn main() {
    let original = String::from("Rust");
    let copy = original.clone();
    println!("{original} и {copy}");
}
```
```expect
Rust и Rust
```
hint: Сейчас значение переезжает в `copy`. Нужна копия.
hint: `let copy = original.clone();`

:: recap
- `.clone()` делает полную копию. Работает, но стоит времени.
- Числа, `bool`, `char` — тип Copy, копируются сами.
- `String`, `Vec` — перемещаются.

## LESSON m05-5 | Возврат владения | 5
:: goals
- Как функция может вернуть владение
- Почему это неудобно и что будет дальше

:: text Функция может отдать обратно
Функция забрала значение. Но может его и **вернуть**:

```rust
fn add_world(mut s: String) -> String {
    s.push_str(", мир");
    s
}
```
`push_str` дописывает текст в конец строки.

:: code
```rust
fn add_world(mut s: String) -> String {
    s.push_str(", мир");
    s
}

fn main() {
    let greeting = String::from("Привет");
    let greeting = add_world(greeting);
    println!("{greeting}");
}
```
```out
Привет, мир
```

:: text Неудобно, правда?
Каждый раз отдавать и забирать обратно — утомительно. Как давать другу книгу, только чтобы он сказал, сколько в ней страниц.

Хочется дать **посмотреть**, не отдавая. В Rust это есть. Называется **заимствование** — тема следующего модуля.

:: quiz
Зачем `add_world` возвращает `s`?
[x] Чтобы вернуть владение строкой обратно в `main` => Верно. Иначе строка удалилась бы в конце функции.
[ ] Чтобы напечатать её => Печатает `main`, а не функция.
[ ] Так требует синтаксис любой функции => Функции не обязаны ничего возвращать.

:: recap
- Функция может вернуть владение через результат.
- Это работает, но неудобно.
- Удобный способ — заимствование (`&`). Дальше о нём.
