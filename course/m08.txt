# MODULE m08 | Перечисления и match | Один из нескольких вариантов

## LESSON m08-1 | enum — один вариант из списка | 6
:: goals
- Что такое перечисление `enum`
- Как хранить в вариантах данные

:: text Выбор из списка
**Перечисление** (enum) — тип, значение которого — **один** вариант из заранее известного списка.

```rust
enum Light {
    Red,
    Yellow,
    Green,
}
let now = Light::Red;
```
> Как светофор. Он горит красным, жёлтым или зелёным. Ничего другого быть не может.

:: text Варианты могут нести данные
У каждого варианта могут быть свои данные:

```rust
enum Message {
    Quit,                    // без данных
    Move { x: i32, y: i32 }, // как структура
    Write(String),           // одно значение
}
```
Один тип `Message`, но внутри — разные виды сообщений.

:: quiz
Сколько вариантов одновременно хранит значение типа `Light`?
[x] Ровно один => Верно. В этом и смысл enum.
[ ] Все три => Это была бы структура с тремя полями.
[ ] Ноль или один => Пустым значение enum быть не может. Хотя для «может не быть» есть Option — скоро о нём.

:: recap
- `enum` — один вариант из списка.
- Вариант пишется через `::` — `Light::Red`.
- Варианты могут хранить данные.

## LESSON m08-2 | match — разбор вариантов | 7
:: goals
- Разобрать enum через `match`
- Понять, почему `match` требует все варианты

:: text match — сортировочная машина
`match` смотрит на значение и выбирает подходящую ветку. Это **сопоставление с образцом**.

```rust
match light {
    Light::Red => println!("Стой"),
    Light::Yellow => println!("Жди"),
    Light::Green => println!("Иди"),
}
```
> Как сортировщик посылок: по адресу отправляет в нужное окно.

:: code
```rust
enum Coin {
    Ruble1,
    Ruble5,
    Ruble10,
}

fn value(c: Coin) -> u32 {
    match c {
        Coin::Ruble1 => 1,
        Coin::Ruble5 => 5,
        Coin::Ruble10 => 10,
    }
}

fn main() {
    let total = value(Coin::Ruble5) + value(Coin::Ruble10);
    println!("Всего: {total} руб.");
}
```
```out
Всего: 15 руб.
```
`match` тоже выражение: возвращает значение выбранной ветки.

:: text match проверяет всё
Если забыть вариант, компилятор не пропустит: ошибка `E0004`.

Это огромная помощь. Добавил новый вариант в enum — компилятор покажет **все** места, которые надо обновить.

Не хочешь перечислять всё? Ветка `_` ловит «всё остальное»:

```rust
match number {
    1 => println!("один"),
    2 => println!("два"),
    _ => println!("много"),
}
```

:: code
Данные из варианта достаются прямо в `match`:
```rust
enum Shape {
    Circle(f64),
    Rect(f64, f64),
}

fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => 3.14 * r * r,
        Shape::Rect(w, h) => w * h,
    }
}

fn main() {
    println!("{}", area(&Shape::Rect(2.0, 3.0)));
    println!("{}", area(&Shape::Circle(1.0)));
}
```
```out
6
3.14
```

:: quiz
Что делает ветка `_ =>` в `match`?
[ ] Ловит ошибки => Это не про ошибки, а про оставшиеся варианты.
[x] Подходит под любое значение, которое не поймали раньше => Верно. Это «всё остальное».
[ ] Пропускает `match` целиком => Ветка `_` выполняется, если до неё ничего не подошло.

:: task
Напиши функцию `describe`, которая для числа печатает: `0` → `ноль`, `1` → `один`, любое другое → `другое`. Используй `match`.
```rust
fn describe(n: i32) -> &'static str {
    // твой match
}

fn main() {
    println!("{}", describe(0));
    println!("{}", describe(1));
    println!("{}", describe(42));
}
```
```solution
fn describe(n: i32) -> &'static str {
    match n {
        0 => "ноль",
        1 => "один",
        _ => "другое",
    }
}

fn main() {
    println!("{}", describe(0));
    println!("{}", describe(1));
    println!("{}", describe(42));
}
```
```expect
ноль
один
другое
```
hint: `&'static str` — это просто «текст в кавычках». Странную метку `'static` разберём позже.
hint: Ветки: `0 => "ноль",`, `1 => "один",`, `_ => "другое",`

:: recap
- `match` выбирает ветку по образцу.
- Нужно разобрать все варианты, иначе ошибка.
- `_` — «всё остальное».

## LESSON m08-3 | Option: может быть, а может нет | 7
:: goals
- Почему в Rust нет `null`
- Как работать с `Option`

:: text Значения может не быть
Часто результата может не оказаться. Например, ищем пользователя, а его нет.

Во многих языках для этого есть `null` — «ничего». Его изобретатель назвал `null` своей «ошибкой на миллиард долларов»: программы постоянно падали, забыв проверить.

В Rust `null` нет. Вместо него — `Option`.

:: text Option — коробка, которая может быть пустой
```rust
enum Option<T> {
    Some(T), // внутри есть значение
    None,    // пусто
}
```
> Подарочная коробка. Внутри может лежать подарок (`Some`), а может быть пусто (`None`). Пока не откроешь — не знаешь. И Rust заставит открыть.

`T` — «любой тип». Об этом подробно в модуле про обобщения.

:: code
```rust
fn divide(a: i32, b: i32) -> Option<i32> {
    if b == 0 {
        None
    } else {
        Some(a / b)
    }
}

fn main() {
    for b in [2, 0] {
        match divide(10, b) {
            Some(result) => println!("10 / {b} = {result}"),
            None => println!("На {b} делить нельзя"),
        }
    }
}
```
```out
10 / 2 = 5
На 0 делить нельзя
```

:: quiz
Можно ли сложить `Option<i32>` и `i32` напрямую: `Some(5) + 3`?
[ ] Да, Rust сам достанет 5 => Нет. Сначала надо проверить, что коробка не пустая.
[x] Нет, сначала нужно достать значение из Option => Верно. Это и защищает от «забыл проверить».

:: text Удобные способы открыть коробку
- `if let Some(x) = value { ... }` — сделать что-то, только если есть значение.
- `value.unwrap_or(0)` — достать значение или взять 0, если пусто.
- `value.unwrap()` — достать, а если пусто — **паника**. Только когда уверен.

```rust
let first = vec![3, 1, 2].first().copied().unwrap_or(0);
```

:: code
`if let` — короткий `match` на один вариант:
```rust
fn main() {
    let names = vec!["Аня", "Боря"];
    if let Some(name) = names.get(1) {
        println!("Второй: {name}");
    }
    if let Some(name) = names.get(5) {
        println!("Шестой: {name}");
    } else {
        println!("Шестого нет");
    }
}
```
```out
Второй: Боря
Шестого нет
```
`get(i)` возвращает `Option`: элемента может не быть. Безопаснее, чем `[i]`.

:: recap
- `null` в Rust нет. Есть `Option<T>`: `Some(x)` или `None`.
- Rust заставляет проверить, есть ли значение.
- `if let Some(x) = ...`, `unwrap_or(запасное)`, `unwrap()` — только когда уверен.

## LESSON m08-4 | let else и цепочки let | 5
:: goals
- Ранний выход через `let ... else`
- Несколько условий через `&&` в `if let`

:: text let else — «достань или уходи»
Часто нужно: «достань значение, а если его нет — выйди из функции». Для этого есть `let ... else`:

```rust
fn greet_first(names: &[&str]) {
    let Some(first) = names.first() else {
        println!("Никого нет");
        return;
    };
    println!("Привет, {first}!");
}
```
После этого блока `first` — уже обычное значение, без `Some`.

:: text Цепочки let (Rust 2024)
В новой редакции Rust 2024 в `if` можно склеивать проверки через `&&`:

```rust
if let Some(age) = maybe_age && age >= 18 {
    println!("Взрослый");
}
```
Раньше для этого приходилось вкладывать `if` в `if`.

:: code
```rust
fn parse_age(text: &str) -> Option<u32> {
    let Ok(n) = text.parse::<u32>() else {
        return None;
    };
    Some(n)
}

fn main() {
    for t in ["25", "abc", "15"] {
        if let Some(age) = parse_age(t) && age >= 18 {
            println!("{t}: взрослый");
        } else {
            println!("{t}: нет");
        }
    }
}
```
```out
25: взрослый
abc: нет
15: нет
```
`Ok(n)` — вариант из типа `Result`. Он про ошибки, мы разберём его в отдельном модуле.

:: quiz
Что обязательно должно быть в блоке `else` у `let ... else`?
[ ] Ничего, можно оставить пустым => Нет: после `else` программа не может идти дальше без значения.
[x] Выход: `return`, `break`, `continue` или паника => Верно. Блок обязан «уйти», ведь значения нет.

:: recap
- `let Some(x) = opt else { return; };` — достань или выйди.
- `if let Some(x) = opt && условие` — цепочка в Rust 2024.
